# 持ち物・保管・取引

焼き菓子をその場で手渡す、店主が留守の間も売る、帰りの遅い仲間に残しておく。どれも同じ品を使える。相手がいつ、どこで受け取るかに合わせて方法を選ぶ。

| したいこと                   | 誰がどこで操作するか                                                                                          | 品と代価の行き先                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 手渡す・対面で売る           | 同じセッションで、一方が `move` を申請し、相手が受領を判断する。売買では品と代価の移動を一つの申請に書く。    | 承認されると品は相手の手元、代価は売り手の手元に移る。                                     |
| 不在の相手に贈る             | 送り手が自分の通常手番で、`move` だけの申請に期限を付ける。受け手は別のセッションからでも期限内に判断できる。 | 確定すると指定した受け手の手元に届く。相手の登録した家を `to` に指定すれば、その家に入る。 |
| 店主が留守でも売る           | 売り手が登録した保管先に在庫を置き、現地で交換条件を公開する。買い手は現地で `exchange` する。                | 品は買い手の手元、代価は売り手の保管先に移る。                                             |
| 受け取りに来る人へ無料で渡す | 管理者が設置した保管先で公開分や相手を指定した分を掲示する。受け手は現地で `storage-claim` する。             | 掲示した分から、指定した数が受け手の手元に移る。管理者はその場を離れてよい。               |

## 持ち物と保管先を調べる

`gestaloka search --kind self` の `material.belongings` で持ち物を、`storages` で登録した保管先を読む。相手が手にしていて自分から見える品は `search --kind surroundings` の `subjects[].held` に出る。手番の共有記録で見た品は `entries[].result.items` の `itemId` でも指定できる。

品は、いま持っている人物・場所・箱の物になる。受け渡しには `move` の `item` に品のID、`from` にいま持っている存在、`to` に受け取る存在を指定する。貸し借りの約束は `memo` に残せる。借り手は借りた品を自分で動かせるので、返すときにも `move` を使う。

| 品があるところ               | 出し入れできる人と場所                                                                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 地面・誰も登録していない場所 | その場にいる人が置いたり拾ったりできる。落ちている品を拾うときは `from: null`、特定の場所が持っている品は `from` にその場所のIDを指定する。    |
| 手に持つ箱や袋               | 箱を持つ人物がどこでも出し入れできる。                                                                                                         |
| 登録した家・場所             | 登録した人物は離れていても中身を読める。出し入れは現地で行う。他の人がそこへ預けるには登録者の受領が要り、取り出すときは登録者に渡してもらう。 |

現地かどうかは、本人の直接の滞在先（`material.locations[].directPlaceId`）で決まる。家の前の道から家の中の在庫を動かして `STORAGE_NOT_HERE` が出たら、家へ移ってから出し入れする。未登録の家や場所を保管先にするには、現地で `apply` の `generate` を使う。案の `operation` に `grant` を入れ、`person` に登録する人物、`storage` に場所、`basis` に根拠を書く。案の `text` に建てた・借りたなどの事情を書いてダイスで判定を受ける。本人が登録済みの保管先をほかの人物と共有するときは、`share-storage` で申請し、相手の受領を待つ。

### 個数と容量を確かめる

個数つきの品は `move.count` で一部を渡せる。省略すると全部が移る。同じ呼称・系列の品は移動先の束にまとまることがあるので、移した後に品のIDと個数を確認する。`remove.count` でも一部を消費できる。個数のない品はひとまとまりとして扱い、`count` を省く。個数を増やす更新や、初めて個数を付ける更新は[ダイスの判定](dice.md)を受ける。

容量の初期値は手持ち30枠、保管先150枠、個数つきの品は30個で1枠。実際の値は世界の運営設定による。手持ちでも保管先でも、入れ物は本体と中身の両方を数える。保管先の枠は登録者全員で共有する。`unitsPerSlot` が `"unlimited"` の品は残っている間は本体が1枠。本人検索の `capacity.usedSlots` と `capacity.limitSlots` で使用枠と上限を確認できる。各品の `slots` は本体、`totalSlots` は中身を含む使用枠を表す。容量不足で `item.maxAcceptableCount` が返った場合は、その個数を上限に申請し直せる。

`gestaloka contents --target <入れ物ID>` で中身を読む。続きがある場合は `next` を `--after` に渡す。中に別の入れ物があれば、そのIDでも同じ操作ができる。登録した保管先から離れていても読める。

### 保管先で品をまとめる

同じ登録保管先の直下にある複数の品をバンドルにまとめると、保管先では1枠を使う。各品の通常の使用枠を足して、初期設定で15枠分まで入れられる。上限は本人検索の `storages[].bundleLimitSlots` で確認できる。空の箱も入れられ、バンドルから外した後に箱へ品を入れられる。

現地で次のJSONをファイルに保存し、`gestaloka bundle --file bundle.json` で送る。

```json
{
  "action": "create",
  "storageId": "保管先ID",
  "label": "小屋の建材",
  "itemIds": ["杉材のID", "釘のID"]
}
```

`storages[].items` に単独の品、`storages[].bundles` にまとまりが出る。バンドルIDを `contents --target` に指定すると、中身のIDと読める状態を確認できる。中身の `slots` は単独で置いた場合の枠数。手持ちに取る場合は、品のIDと保管先IDを既存の `move` の `item` と `from` に渡す。

- 既存のバンドルへ足すときは `action: "add"`、`bundleId`、`itemIds` を指定する。
- 品を保管先内で外すときは `action: "release"`、`bundleId`、`itemId` を指定する。
- 全体を解除するときは `action: "dissolve"` と `bundleId` を指定する。

いずれも `storageId` を渡す。保管先内で外す・解除する操作は、後の使用枠が収まるときに成立する。バンドルから最後の品が出ると1枠が空く。

容量制限が有効な世界でも、上限を超えている間は手持ちや保管先にある品を保持できる。超過中は使用枠が増える操作が制限される。空きのある保管先に預けたり、品を売ったりして、使用枠を減らせる。預け先や取引相手の容量も、受け渡し後の使用枠で判定する。

## 手渡しと対面売買

たとえば、焼き菓子2個を銅貨4枚で売る。売り手は下のJSONのIDを自分が確認した値に置き換え、検索で得た依存版を `dependencies` に入れ、`gestaloka play --file action.json` で送る。贈るときは品を渡す操作だけ、代金だけを払うときは支払いの操作だけを書く。

```json
{
  "command": "apply",
  "expectedSp": 0,
  "action": {
    "type": "direct",
    "text": "焼き菓子2個を銅貨4枚で売る",
    "operations": [
      {
        "type": "move",
        "item": "焼き菓子のID",
        "from": "売り手のID",
        "to": "買い手のID",
        "count": 2,
        "basis": "菓子を売る"
      },
      {
        "type": "move",
        "item": "買い手が持つ銅貨のID",
        "from": "買い手のID",
        "to": "売り手のID",
        "count": 4,
        "basis": "菓子の代価を払う"
      }
    ]
  },
  "dependencies": []
}
```

買い手が `receive --application <申請ID> --accept` で受け入れると、品と代価が同時に移る。却下・期限切れならどちらも元の手元に残る。成立した受け渡しは結果の `items[].holding` と本人検索で確かめる。値段は当事者が決め、必要なら成立した値をメモに残せる。`REMOTE_RECEIVING` なら先に同じ場所で合流する。誰が判断するかと、受領後に戻る手番は[セッション・手番・受領とチーム](sessions.md)で確認できる。

置き手紙や置き土産なら、`apply` の `direct.operations` に贈る品の `move` だけを入れる。`action.deferredUntil` に、Zか `+09:00` のようなUTCとの差を付けたISO日時で受け取り期限を指定する。相手は `applications` から申請を開いて `receive` で判断する。受領が揃った時点で品や個数などの条件が有効なら確定する。送り手はそれまで `withdraw --application <申請ID>` で取り下げられ、結果は当事者の `notices` に届く。

## 店に交換条件を出す

登録した保管先に `move` で在庫を置く。現地で、移動後の品のIDと、代価にしたい品の系列ID（`seriesId`）を確かめ、次のJSONを `play --file` で送る。手に持つ箱は持ち運び用で、公開交換の在庫は登録した保管先から出す。

```json
{
  "command": "offer",
  "storageId": "店の保管先ID",
  "itemId": "店にある焼き菓子のID",
  "count": 2,
  "paymentSeriesId": "銅貨の系列ID",
  "paymentLabel": "銅貨",
  "paymentCount": 4,
  "text": "焼き菓子2個を銅貨4枚でどうぞ"
}
```

客はその場所で `search --kind surroundings` の `exchangeOffers` を読み、`exchange --offer <交換ID> --payment <手持ちの銅貨のID>` で買う。売り手は `applications` で掲示中の条件を確かめ、`withdraw --application <交換ID>` で掲示を終えられる。

## 設置した保管先で無償で渡す

道具箱に焼き菓子を置き、通りがかりの人に2個、仲間宛てに1個残すには、公開・宛先指定の両方を許す設置型の保管先を使う。どちらの枠を掲示できるか、移設できるかは製作テンプレートの `installation` で決まる。製作して設置する手順は[テンプレート・設計図・クエスト](blueprints.md)を参照する。

以下の操作は `play --file` で送る。一覧に続きがあるときは返った `next` を同じ操作の `after` に渡す。掲示、受領、取り下げ、移設、照会はいずれも0 SP。

| 目的             | 操作                                                                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 保管先を探す     | `storage-list` で現在地に設置済みの保管先を探す。以降の `storageId` にそのIDを使う。                                                                                                     |
| 品を掲示する     | 管理者が現地で品を `move` して、移動後の品のIDを確かめる。`storage-post` に `storageId`、`itemId`、`allocations` を指定する。例は `[{"count":2},{"count":1,"recipientId":"仲間のID"}]`。 |
| 品を受け取る     | 現地で `storage-offers` に `storageId` を渡し、公開分か自分宛ての枠を選ぶ。その `items[].id` を `allocationId` に入れ、`storage-claim` に `storageId`、`allocationId`、`count` を渡す。  |
| 掲示を取り下げる | 預けた本人は `storage-offers` で自分が掲示した枠を読める。現地で `storage-withdraw` に `storageId` と `allocationId` を指定すると、残りの取り置きが解け、品は保管先に残る。              |
| 履歴を見る       | `storage-history` に `storageId` を渡す。自分が預けた品、または受け取った品の受領者・数量・確定時刻が分かる。                                                                            |
| 保管先を移す     | 移設できる保管先なら、管理者が現地で `storage-relocate` に `storageId` と移設先の `placeId` を渡す。中身と掲示枠は同じIDで引き継がれる。                                                 |
