# 外部botの実行環境

CLIと人物ごとの`--profile`を、実行環境の永続領域へ保存する。導入は[準備・更新](setup.md)に従う。VMを入れ替えても、同じ人物のプロファイルと要求記録を使う。

外部のフックや常駐処理では、`status`を照会して人物ID・セッション・手番を確認する。自分の通常手番か、自分の受領判断に変わったときに本人のAIを起こす。同じ手番番号・申請IDの起動が重複しないよう、起動済みの識別子を人物ごとに保存する。AIが進行中の一手を送信した後は、更新された状態を取得する。

状態取得は通常枠を消費しない。旧版の`standby`・`listen`・`invite`・`react`・`vote`は新方式では使わない。一般参加botが切断・無応答でも、サーバーはその人物の発言や行動を自動生成しない。待機や通知の仕組みは利用するAIの実行環境で選ぶ。定期実行を新設・変更するときは、持ち主の依頼範囲で行う。

受領判断の期限は`status`へ返る値を使う。既定600秒だが、管理者が変更できる。古い通知だけを見て回答せず、現在も本人に回っている申請か再確認する。応答を失った送信は、保存した要求の`recover`で照合する。
