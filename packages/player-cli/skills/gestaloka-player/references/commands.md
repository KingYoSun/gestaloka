# 世界への申請

世界を変更する申請は `gestaloka play --file <JSONファイル>` で送ります。共有世界を変更するリクエストでは、`command` に `apply`、`action` に操作の種類と対象を指定します。対象には、本人が照会で得たIDを使います。CLIが要求IDを作って保存するので、返答を失ったときは `recover` で照合できます。

`play --file <JSONファイル> --quote` で、申請を送る前に必要SPを確認できます。表示された額を `expectedSp` に指定します。新規抽選が起きた生成案は成否にかかわらず各1 SPです。材料不足や権限不足で抽選前に止まった案は消費しません。正式改名は採否を保存した審査1件につき1 SPで、ダイスは振りません。

## 用途別の更新

| action.type     | 直接変えるもの                                             | 必要SP      |
| --------------- | ---------------------------------------------------------- | ----------- |
| `direct`        | 本人や同行者の移動、物品の受け渡し・消費、保管先登録の終了 | 0           |
| `generate`      | 物品の製作、技能の習得・発展、保管先の初回登録             | 原案ごとに1 |
| `share-storage` | 本人が登録済みの保管先を受領によって共有する               | 0           |
| `state`         | 指定した存在の状態                                         | 1           |
| `oppose`        | 同席する人物・個体への対抗                                 | 1           |
| `rename`        | 対象の正式な呼び名                                         | 1           |
| `clarify`       | 習得済みの技能の適用範囲を保った説明の訂正                 | 0           |
| `detach`        | 本人に付いている着脱可能な物の関係の終了                   | 0           |
| `interpret`     | 本人が対象をどう捉えたか                                   | 0           |

`direct.operations` の物品・移動の型には `locate`、`move`、`remove`、`revoke` があります。品と代価を同時に移す場合は二つの `move` を同じ操作に含めます。

```json
{
  "command": "apply",
  "expectedSp": 0,
  "action": {
    "type": "direct",
    "text": "指定した場所へ移動する",
    "operations": [
      {
        "type": "locate",
        "subjectId": "本人のID",
        "text": "移動先の名前",
        "aboutIds": ["移動先のID"]
      }
    ]
  },
  "dependencies": []
}
```

時間差の受領が必要な受け渡しでは、`deferredUntil` を `action` に指定します。使える条件は [時間差の受領](sessions.md) を参照してください。

### 物を使って何かを変える

製作・習得は `generate.plans` に、説明と直接の操作を案ごとに入れます。必要な材料は案の `materials` に物品IDと個数を指定できます。独立した案を同じ申請で送っても、成否とSPは案ごとに扱います。時間指定は物品製作案1件に `waitMinutes` を付けます。

```json
{
  "command": "apply",
  "expectedSp": 1,
  "action": {
    "type": "generate",
    "plans": [
      {
        "text": "木片を削ってしおりを作る",
        "operation": {
          "type": "create",
          "label": "木のしおり",
          "holder": "本人のID",
          "basis": "木片を薄く削り、表面を磨く"
        }
      }
    ]
  },
  "dependencies": []
}
```

技能の発展に使う元技能は、操作 `learn` の `consumeSkillIds` に指定します。元技能を使うのは発展が成功した場合です。

## 本人の呼称と状態を改める

`rename` には対象IDと新しい `name` を指定します。技能の能力本文と習得根拠は同じ技能に残ります。技能の説明を訂正するときは `clarify` に技能IDと新しい `text` を指定します。能力の追加や制約の変更は、新しい習得・発展を申請してください。

`state` には影響を受ける `targetId`、行為の `text`、成立したときの `description` を指定します。既存の状態を置き換える場合は `stateId` に、本文のノードIDではなく状態の関係IDを指定します。着脱可能な物を付けるときは `attachedItemId` を指定できます。場所の効果を後の移動に反映させるときは `affectsMovement` を指定します。たとえば広場に霧を作る申請は広場に対して1 SPです。霧を後の移動条件として読んでも、術者への追加課金はありません。

`oppose` には相手のID、行為の `text`、成功時に外から観察できる `description` を指定します。

## 新しい場所

探索は `explore` で申請します。接続元と呼び名を指定します。既知の場所との同一性や、道と場所の説明は探索の判定で扱います。
