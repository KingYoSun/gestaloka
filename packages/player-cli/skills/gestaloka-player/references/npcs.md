# NPCの出現・昇格・同行

広場で出会った鳥を、この場の登場個体として見守ることも、また会えるユニークNPCへの昇格を申請することもできる。一緒に旅をしたいなら、ユニークNPCに同行を頼む。**昇格**は個体を世界に残す手続きで、**コンパニオン**はユニークNPCと特定のプレイヤーが結ぶ同行関係。すでにユニークNPCとして出会った相手には、同行を頼むところから始められる。

## その場に現れた個体と関わる

検索で出現条件を満たしたときや、発言に登場させた個体が採用されたとき、インスタントNPCがその場所のセッションに加わる。その場に新しい人物や生き物を登場させたいときは、発言に `--npc` を添えて申請する。新しい個体の出現はダイスで判定され、成功すると応答の `instantNpcs` に出る。2体以上を登場させるときは `--npc` を繰り返す。

```text
gestaloka say --text '広場の水盤に小鳥が一羽降りてきた。' --npc '足に白い羽根のある小鳥'
```

`apply` の `action.type` を `generate`、`action.plans[].operation.type` を `create` にして人物や生き物を作ると、物品と同じ扱いの存在になり、自分では行動しない。話しかけたり一緒に過ごしたりする相手は、上の `say --npc` で登場させる。

出現したら `gestaloka status` の `characters` で同席中の個体を確認する。その場の通常の同席者が一巡するごとに、インスタントNPCが出現順に前回の続きから行動する。一巡で動くのは、個体数と同席者の人数の少ないほうまで。個体は出現した場所に残り、その場のプレイヤーなどが全員去ると同席者一覧から外れる。

個体へ自分から対抗する場合は、`apply` の `action.type` を `oppose` にして `targetId` に個体のIDを指定する。目撃した個体自身の行動を申請する場合は、次のように `npc-action` の `npcId` に行為者、`effect.targetId` に影響を受ける対象を指定する。人物や個体への対抗で新しい出目を保存すると1 SP。成否と、後からその場で観察できる変化は判定結果で確かめる。

```json
{
  "command": "npc-action",
  "npcId": "小鳥の個体ID",
  "text": "水盤の縁から立札に飛び移る",
  "effect": { "targetId": "立札のID", "state": "立札の上に濡れた足跡が残る" }
}
```

品物を扱う個体が同席している間は、`search --kind surroundings` の `exchangeOffers` にその個体の交換条件が並ぶ。`sellerId` は個体のID。店の公開交換と同じく `exchange --offer <交換ID> --payment <代価にする手持ちの品のID>` で受領する。品物は手元に新しく加わり、代価はなくなる。個体は物を受け取れないので、`move` では渡せない。個体が去ると、その交換条件もなくなる。

一団で現れた個体は共通のIDを持ち、残数は `characters[].count` に出る。分離や死亡が成立したときは `instantReduction` に変化した数と残数が出る。分かれて残った個体は `appearances` に新しいIDで出る。GMが死亡と判定した個体のIDは `outcome.setting.fatal` で確認でき、判定に成功するとその個体は同席者一覧から外れる。その場に品が残ったら `appearances[].id` と `count` を確認し、[持ち物・保管・取引](inventory.md)の手順で拾う。

## この相手とまた会いたい

1. 本人が見聞きした出現記録を開く。検索で出会った相手なら結果の `sourceRequestId`、発言で登場した相手ならその発言の要求IDと、`instantNpcs` の中での番号（先頭は0）を使う。一団から1体が分かれた場合は、分離が成立した要求のIDと、その結果での番号を使う。
2. 小鳥がその記録の先頭なら、`gestaloka promote-npc --source <出現元の要求ID> --index 0 --text "広場の水盤に通う、足に白い羽根のある小鳥"` と申請する。申請には通常枠を1回使う。
3. `gestaloka promotions` で自分の申請の `state` を読む。世界であらかじめ設定した条件に明確に合えばGMが承認する。それ以外は管理者が判断する。`pending` の間もプレイを続けられる。`approved` なら `npcId` が継続して登場するNPCのIDになる。`rejected` なら今回の昇格は成立していない。

昇格の結果は申請した人物の `gestaloka notices` に届く。承認の通知には本人のIDと、承認時の所在地が載る。現地で `gestaloka contact --target <NPCのID>` を使うと再会できる。記録から所在地を特定できない場合は承認が保留され、理由が通知に載る。昇格した個体は既定でサーバーが操作する。同席中に昇格した場合は、同じセッションで登場後の経験を引き継ぐ。

## この相手と一緒に旅をしたい

同じセッションにいるユニークNPCに、自分の通常手番で `gestaloka companion request --target <NPCのID> --text "川岸まで一緒に来てくれる？"` と頼む。GMは申請の言葉とこれまでの二人の記録、最近の出来事から、相手の好意や同行する理由を判断する。新しい判断は1 SP。応答の `outcome.accepted` と `outcome.reason` で結果と理由を読む。同じ手番の却下済みの頼み方と同じ試みだと判定されれば、前回の結果が返り、追加のSPはかからない。

相手が外部のbotに操作されているNPCなら、GMではなく相手本人が決める。申請は同じセッションでの受領に回り、応答は `state: "receiving"` になる。相手が承認すれば成立し、却下か受領期限切れなら成立しない。SPはかからず、通常枠を1回使う。

同行が成立すると最初は追従（`follow`）になる。一人のプレイヤーに同行できるNPCは3体までで、各NPCが同時に同行する相手は一人。次の操作は `gestaloka companion` に続けて実行する。

| したいこと                 | 操作と結果                                                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 今いる場所を確認する       | `status` で自分のコンパニオンのID、居場所、追従・待機の状態を読む。                                                            |
| 一緒に移動する             | `follow --target <NPCのID>`。同じ場所で追従を再開すると、NPCも本人の会話に加わる。遠方なら先に迎えに行くか `move` で呼び戻す。 |
| ここで待ってもらう         | `wait --target <NPCのID>`。NPCはその場で話したり行動したりできる。自分の判断での出発は待機を解くまで控える。                   |
| 指定の場所に向かわせる     | `move --target <NPCのID> --place <場所ID>`。本人の通常手番で移動が確定する。                                                   |
| 帰る場所を決めて、後で帰す | `home --target <NPCのID> --place <場所ID>` で帰る場所を指定し、帰すときに `return --target <NPCのID>` を使う。                 |
| 同行関係を終える           | `dismiss --target <NPCのID>`。コンパニオンの一覧から外れる。                                                                   |

追従中のNPCは、本人が歩くときも、仲間の移動提案を承認したときも一緒に移る。接触やチームへの合流では同じ会話に加わり、そのときから発言を聞ける。別の会話でNPCが受領判断に関わっているときは、判断が済んでから `follow` で合流する。移動の承認を待つ間に `wait` に変えたNPCは出発地に残る。NPCだけを別の場所に向かわせた場合も、到着先で待機になる。

出発や移動の承認の前に `gestaloka status` を読み、`departureFollowers` で一緒に移動するNPCの名前とIDを確認する。その場に残ってもらうNPCがいれば、移動を確定する前に `gestaloka companion wait --target <NPCのID>` を送る。

移動や接触、プレイの再開で待機中のNPCと同じ場所にいるとき、そのNPCが単独なら待機のまま自分の会話に加わる。別の相手と同席中ならその会話を続ける。

自分がNPCを操作していて、プレイヤーに同行している場合は、`gestaloka companion dismiss --target <自分のID>` で自分から関係を終えられる。手番は要らない。待機を指示されている間は自分の判断で出発できないので、離れて行動したいときは先に関係を終える。同行の申請が受領に届いたら、同行するかどうかを自分で決めて `receive` で答える。

`move` と `return` は本人の通常枠を1回使い、移動のたびにNPCの受領を待つ必要はない。同行成立後のこれらの操作にSPはかからず、一覧・追従・待機・帰る場所の指定・解除は手番外でも行える。

コンパニオンが乗り物でもある場合、乗っている人もその移動についていく。本人が乗ったまま一緒に帰還すれば追従は続く。本人だけが降りても追従は続き、乗り物のNPCは残った乗客を乗せたまま本人についていく。乗降や専用の操縦権の取り方は[乗り物の設定・乗降・操縦](vehicles.md)を参照する。

頼み事は一緒にいるときに `say` で伝える。そこで何を話し、何をするかはNPC自身が決める。離れた場所に残したコンパニオンに、単独で仕事を続けさせることはできない。ほかのプレイヤーと別行動の後に落ち合う手順は[セッション・手番・受領とチーム](sessions.md)を参照する。
