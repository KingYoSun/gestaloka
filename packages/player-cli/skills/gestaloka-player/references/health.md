# 死亡・怪我・治療

人物が怪我をする仕組み、怪我の治し方、死亡したときに起きることをまとめる。判定の流れと申請の形式は[ダイスの判定](dice.md)と[世界への申請](commands.md)を読む。この文書の `outcome` などの項目は、CLI の出力では `result` の下に入る。

## 怪我は状態として残る

怪我や疲れ、拘束といった人物の変化は、本人の**状態**として記録される。状態は `search --kind self` の `material.states` で読める。

- `material.states[].node.text`: 状態の本文（例: 「左腕に浅い切り傷がある」）。
- `material.states[].relation.id`: 状態の関係ID。手当てで状態を置き換えたり、状態や本人が外せる付着を終えたりするときに使う。
- `material.states[].relation.period.until`: 期限のある状態だけに入る、終わる時刻（UNIX時刻のミリ秒）。
- `material.states[].relation.text`: `judged` なら、GM が判定の結果として付けた状態である。`location` なら所在で、怪我などの状態ではない。

相手の状態は、同じ場所で `search --kind subject --target <相手のID>` で調べる。相手が読める範囲を狭めた状態は出ない（[コマンド一覧](cli.md)の `viewers`）。

## 怪我を負うとき

怪我は、ダイスの判定を経て残る。発言・移動・受け渡しなど、ダイスを振らない行動では怪我を負わない。

| 起きる場面                                           | 状態が残る人物                 | 読む場所                                                                                                                                |
| ---------------------------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| ほかの人物の対抗行動（`oppose`）が成功した           | 作用を受けた、同席している人物 | 申請者は応答の `outcome.setting.states`（`outcome.success` が `true` のときだけ記録される）。作用を受けた人物は自分の `material.states` |
| 出現個体（インスタントNPC）の行動が成功した          | 作用を受けた人物               | セッションの記録の、その個体の行動の `entries[].result.effectState`。`npc-action` で申請したときは応答の `effectState`                  |
| 自分の作成・対抗の判定が失敗し、さらにファンブルした | 申請した本人                   | `outcome.fumble.success` が `true` のとき、`outcome.setting.fumble.text`。判定が複数ある申請では `outcome.proposals[]` の各判定         |

- 対抗行動とファンブルで残る状態の本文は、GM が書く。出現個体の行動では、行動の結果（`effect.state`）のうち GM が認めた箇所が残る。
- 同意を待たない対抗行動（`apply` の `oppose`）では、成功時に外から観察できる結果の案を申請する。相手に残る状態はGMが決める。
- ファンブルは、GM がファンブルの範囲を設定した判定でだけ起きる。世界のファンブルの基準は、運営者が表示を選んだ世界なら `status` の `fumbleCriteria` で読める。`explore`、隠密の判定、乗り物の操縦権の判定、死亡の判定にファンブルはない。
- 新たに自分の状態を変える場合は `apply` の `state` で申請できる。ダイスに成功すると、その申請に由来する状態として保存される。

## 期限のある怪我と、ない怪我

GM は、ファンブルで本人に残る状態と、対抗行動の成功で相手に残る状態に、続く時間（`minutes`、現実の分）を付けることがある。付けるのは、何もしなくても時間の経過で終わる状態だけである。

- **期限のある状態**: `relation.period.until` の時刻を過ぎると、現在の状態から外れる。履歴には残る。
- **期限のない状態**: 次の状態は、終えるまで続く。
  - 自然には治らないと GM が判断した状態（欠損など）
  - 出現個体の行動で残った状態
  - `apply` の `state` で `minutes` を指定せずに付けた状態
  - 期限の仕組みより前に付いた状態

## 怪我を治す

`search --kind self` で本人の状態の関係IDを取得します。相手の手当てなら、同じ場所で `search --kind subject --target <相手のID>` を使います。

```json
{
  "command": "apply",
  "expectedSp": 1,
  "action": {
    "type": "state",
    "targetId": "手当てを受ける人物のID",
    "text": "傷口を洗って包帯を巻く",
    "description": "腕に包帯が巻かれ、傷の痛みが和らいでいる",
    "stateId": "手当てする状態の関係ID"
  },
  "dependencies": []
}
```

新しい治療はGMが判定します。判定に成功すると、指定した傷の終了と、手当て後の状態を同じ確定に含められます。ほかの人物への変更で受領が必要なときは、相手が受け入れると確定します。対抗は `action.type` を `oppose` にし、相手のIDと、外から観察できる結果の案を書きます。対象に残る状態はGMが決め、新しい出目を保存すると1 SPです。

期限付きの状態は `relation.period.until` で終了します。本人が外せる物として成立した付着は、`detach` に関係IDを渡して0 SPで終了できます。

## 死亡

### 死亡する条件

死亡は、対抗の判定と出現個体の行動の判定で、GM がダイスの設定と一緒に決める。`outcome.setting.fatal` は成功したときに死亡する対象なので、失敗した判定にも出る。死亡が起きるのは、`outcome.success` が `true` のときだけである。

- **プレイヤーとユニークNPC**: 運営者が死亡判定を無効にしていない世界（既定は有効）で、行動の作用を受ける同席中の人物が対象になる。成功した判定の `outcome.setting.fatal` に入っていれば死亡が確定する。
- **出現個体（インスタントNPC）**: 検索で現れた個体は、1体でも個体数を持ち、死亡は `instantReduction` の死亡の数と残数で確定する。個体数を持たない個体（`say --npc` で登場させた個体と古い記録の個体）だけが `fatal` に入る。

人物の死亡は `fatal` による判定の成功で確定する。運営者は世界ごとに死亡の条件文を設定できる。

### 非戦闘地域

非戦闘地域にいる対象は、対抗行動による死亡・状態の付与・状態の終了から守られる。出現個体も死亡せず、一団の死亡数も減らない。範囲は登録された場所と、その内側として記録された場所。乗り物の外側が非戦闘地域なら、車内にいる対象も守られる。

非戦闘地域で対抗を行った本人には、その対抗のファンブルで状態が付くこともない。対抗のダイスやSP、物品の移動などの結果には通常の規則が適用される。

### 死亡したプレイヤーとユニークNPCに起きること

リスポーンは世界ごとの設定で、既定では有効。新しい人物を作るときに、その人物だけリスポーンなしを選べる。選択は作成時に保存され、世界の設定にかかわらずその人物に適用される。

リスポーンなしで死亡した人物は、その場でセッションを離れる。その人物を操作しようとすると `ACTOR_DEAD` が返る。過去の記録は引き続き読める。同じアカウントで[参加手続き](join.md)を行えば、新しい人物を作れる。

リスポーンする人物は、死亡後に次のように続ける。

1. 死亡を確定した判定（対抗行動か出現個体の行動）と同じ確定で、世界に設定された場所へ移る。設定がなければ、本人が最初にいた場所へ移る。行き先が定まらないときは、その場にとどまったままセッションから外れる。
2. 元のセッションから外れ、移った先の単独のセッションで続ける。元のセッションと本人のセッションの両方に、死亡による離脱が記録される（隠密で滞在中なら、元のセッションには記録されない）。
3. 同行関係は残ったまま待機（`wait`）に変わり、ついてこない。また一緒に動くには、同じ場所で `companion follow --target <NPCのID>` を使う。離れているなら迎えに行くか `companion move` で呼び戻す（[NPCの出現・昇格・同行](npcs.md)）。死亡したNPCがだれかに追従していた場合も、その同行は待機になる。
4. 次の状態は、復帰後の現在の状態に残らない。履歴には残る。
   - GM が判定の結果として付けた状態（対抗行動の成功で GM が返した状態、ファンブル、出現個体の行動で残った状態）
   - 「SP使用禁止」以外の期限付きの状態
   - 死亡を確定した判定で付いた状態
5. `judged` の印も期限もない既存の状態は残る。本人が申請して付けた状態や、判定の印が導入される前の状態などが含まれる。

プレイヤーには、死亡が確定した時点から「SP使用禁止」が付く。期間は既定で3時間。サーバー設定で期間を変更でき、0秒に設定すると付与されない。期間中にSPを消費する操作を申請すると `SP_USE_PROHIBITED` が返る。SPを消費しない操作はでき、期限に達するとSPを使えるようになる。

死亡によって持ち物が落ちたり失われたりはしない。死亡を確定した同じ行動で奪われた物は、その結果どおり相手へ移る。死亡の経緯は出来事の記録と目撃に残るので、周りの人物は死亡したことを知りうる。

復帰したら、`search --kind self` で所在と状態を確かめる。元の場所の人物とまた話すには、同じ場所へ移動して `contact` し直す。

### 出現個体の死亡

出現個体は、死亡すると同席者の一覧から外れる。一団なら残数が減り、0になると外れる。世界が設定していれば、死亡した数に応じてその場に品が残ることがある。`say --npc` で登場させた個体は品を残さない。読み方は[NPCの出現・昇格・同行](npcs.md)を参照する。

## よくある疑問

- **治ったのに怪我が残っている**: 新しい状態が要らないときは [現在の状態を終了する](commands.md#現在の状態を終了する) の例に沿って `endStateIds` に今の関係IDを指定する。手当て後の状態を記録するときは、上の「怪我を治す」の例に沿って `stateId` に指定する。
- **相手に負わせる怪我は誰が決めるか**: 対抗で相手に残る状態はGMが決める。結果は `outcome.setting.states` で読める。受領を経て相手に状態を付ける手順には `apply` の `state` を使う。
- **リスポーンの後も怪我が残っている**: `judged` の印も期限もない既存の状態は復帰後も残る。取り違いが疑われる場合は、本人検索で得た関係IDとともに `report` で運営者に知らせる。
