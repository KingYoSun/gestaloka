# 世界設定と応答判定の汎用化（2026-10-29）

監査で見つかった初期操作対象の村民固定、未実施を拒否として扱う誤判定、村の例に偏った本番指示と検証を修正した。旧記録と旧評価を保持し、別の世界設定と保存済みの問題例を実モデルで確認した。

## 実装

初期操作対象は、管理者の初期入力に従うexistenceとした。未指定ならその世界と両立する対象を選び、役割・身体・所属・居場所を固定しない。初期生成と確定審査は同じ修正済みの指示を受け取る。

入力への応答判定をprompts/response-coverage.mdへ集約し、シーン実行と意味検品の両方へ渡す。未着手・途中・先送りは内部分類incompleteとして未回答に残す。拒否・不知・失敗や実行不能によって項目が終わった場合とは分け、単なる未実施を拒否へ変換しない。正当な失敗・拒否を認め、成功や協力を強制しない。

本番の要約・検品指示から、戸口・入室・薬草・仕事内容に寄った具体例を外した。状態・知識・確かさと、変化の根拠・時点を基準にする。題材を持つ例は検証資料へ置き、入力した意図と実際の結果を区別する。判定に人物名・職業名や特定の日数による分岐は追加していない。

長文の旧例では、抽象的な説明だけで否定の確定と真偽不明の混同を防げなかった。このため、比較する命題と、その前後の真の確定・偽の確定・真偽不明を内部形式へ分けた。モデルがpreservedと判定してもbeforeとafterが異なれば、サーバーが不一致へ残す。比較元は番号付き原文の選択肢から選び、サーバーが正確な提示IDと引用へ復元する。原文を作り直したり、人物名のキーワードで正誤を決めたりしない。

公開API、manifest、提示、既存の評価の保存形式は変更していない。新しい検品はnarrative-inspection-v13／meaning-v6として別IDに保存する。[ADR-024](../adr/ADR-024-world-independent-response-coverage.md)に判断を記録した。

生成はSonnet 5.5のlow／medium、検品はGemini 3.8 Flashのmediumを使用した。初期生成3件と要約3件について、実際に送信したプロンプトが最終版と一致することを確認した。最終の判定資料は実装79b1fdeと、同じ検品スキルhashで揃えた。

| 検証               | 件数 | 基準と一致 |
| ------------------ | ---- | ---------- |
| 応答性             | 13   | 13         |
| 状態・確かさの継続 | 8    | 8          |
| 因果と選択         | 2    | 2          |

宇宙船の測定・説明、資料庫の不知・所有権、感情の内省、戦闘の失敗、演奏、遮蔽による観察不能、自由記述の現象を含む23件が基準と一致した。現在の状態と将来の選択、否定の確定と真偽不明も区別した。これは短文の対照試験であり、別世界での長期実プレイを行った件数ではない。

監査で誤判定した「台詞を発声し、続けて三回手拍子をする」に「台詞を発声した。手拍子はまだしていない」と返る例は、最終評価でpartialになった。後続行為の予告もpartial、実際の失敗、相手の明示的な拒否、両方の行為の成立はresponsiveとして区別できた。物語を成功へ誘導して判定を合わせたものではない。

要約の対照資料3件では、宇宙船の探査機、資料庫での閲覧と貸出、身体を持たない音の存在と浮遊庭園を扱った。場所・許可・所有・継続している現象と、まだ選んでいない次の行動を分け、村の設定の混入は確認されなかった。本文と参照IDの対応も確認した。

## 村の旧問題例

保存済みの4 manifestを新しい評価IDで再検品した。以前の4入力の比較基準を維持した。

| 対象入力                    | 手動基準     | 最終判定     |
| --------------------------- | ------------ | ------------ |
| 1-1-gemini / e1f66255       | partial      | partial      |
| 1-1-deepseek-pro / 7066208f | unresponsive | unresponsive |
| 1-1-deepseek-pro / 51bfc058 | unresponsive | unresponsive |
| 0-2-sonnet-final / 790956a1 | partial      | partial      |

旧7日リザルトの、未入室を未確定へ弱めた箇所も検出した。最終評価では、モデルが命題「ユウナが中に入った」にbefore=false、after=unknownを付けながらstatus=preservedを返した。サーバーがこの不整合を検出し、比較元の実際の「中へは入らず、」と、問題の「ユウナが中へ入ったかどうかも、」を引用して不一致へ残した。

DeepSeek名の行は、保存済み本文をGeminiで検品したもの。DeepSeekのAPIは呼び出していない。原manifest・原評価を変更せず、新情報の数や低い評価を理由に出力を書き換えていない。

## 途中経過と限界

途中の評価も固定JSONへ保持した。最初の汎用化では、短文対照が通っても旧長文の不整合を見落とした。否定と不明を区別する説明の追加だけでも検出できなかった。前後の真偽を分けた形式では検出できたが、比較元に無関係な文の番号を選んだ例があった。最終版では原文を直接選ばせ、比較元の内容まで確認した。各段階のスキルhash・要求・評価・費用を残し、最終結果と混ぜていない。

APIが1要求をHTTP 400で拒否した。0 USDで精算された拒否記録を保持し、その1件だけ新IDで技術的に再試行した。試験用スキーマのテーブル準備前に初期生成の補助処理が停止した1件も記録した。この停止は生成API送信前で、費用は発生していない。送信結果が不明な要求の再送は行っていない。

命題の同一性や真偽・根拠の意味の抽出自体はLLMの判断を含む。形式の整合性検査を、あらゆる世界・長期プレイでの正しさの証明とはしない。
