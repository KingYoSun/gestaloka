# 生成GMの送信入力と費用の調査

2026年11月22日0時から24時まで（日本時間）に、ぶー村で生成GMを101回ずつ呼び出した2アカウントを比較した。AとBはIssueの匿名表記に対応する。台帳の計算額はAが2.5634242ドル、Bが0.5149886ドルだった。Aの入力が大きかった主な理由は、申請者の手持ち、技能、登録保管庫の中身、材料候補だった。Aの序盤から終盤にかけての増加は、主に新しく習得した技能の本文と習得経緯による。[Issue #418](https://github.com/KingYoSun/gestaloka/issues/418)

## 11月22日の台帳と送信入力

対象202件はいずれもOpenAI Responsesの `gpt-6.1-terra`、推論設定 `medium`、同一設定版・適用単価で完了していた。台帳の保存済み `request.input` から送信済みテキストを集計した。Aは101件すべてが1案、Bは1案99件、2案1件、4案1件だった。調査のためのGM呼び出しは発生していない。

申請者の手持ちが差の29.1%、技能が21.7%、保管庫の中身が21.6%、消費候補が11.4%を占めた。Aでは、直前の呼び出しでも同じ内容で送った行が、申請者の手持ちで94.2%、保管庫の中身で95.7%だった。

保管庫の中身はAで平均103.7行、うち申請の本文・変更内容などにID・短縮ID・呼称が現れたか、材料候補にIDが現れた物品は平均2.6行だった。保管庫そのものにも物品にもこの条件で一致がなかった行は平均74.1行、8,549バイトだった。この照合で分かるのは文字列上の一致までである。たとえば、申請が品名を明示せずに材料や道具の提案を求めたときは、一致しない行も判断に関わり得る。保存入力には当時の距離を特定する情報がそろっていないため、遠隔保管庫だけの寄与は求められない。

## 技能が増えたときの入力とキャッシュ

| 期間       | Aの平均入力トークン | Bの平均入力トークン | Aの平均技能数 | Aの技能の平均バイト数 |
| ---------- | ------------------: | ------------------: | ------------: | --------------------: |
| 最初の20件 |              23,919 |               9,638 |          10.6 |                 7,009 |
| 最後の21件 |              37,893 |               9,029 |          41.3 |                52,413 |

Aの送信テキストは序盤から終盤にかけて1回あたり49,322バイト増え、うち技能が45,404バイト（92.1%）を占めた。技能の習得経緯が32,738バイト、本文が10,111バイト増えた。Aでは同じ送信入力内に完全一致する技能の本文・習得経緯がなかった。完全一致する文字列を辞書にまとめる方式をBに当てはめると1回あたり1,314バイト減る試算だが、Aの増加には効かない。

全件で、世界設定と申請者の技能を載せたブロックの直後に、30分の明示キャッシュ境界があった。判定指示から境界までの内容はAで34種類、Bで5種類だった。Aで直前の内容から変わった33回はすべて技能が増えた回で、その33回ではキャッシュ読取が0だった。30分書込はAで342,441トークン、Bで57,002トークンだった。境界の後ろにある手持ちや保管庫の明細は、その境界でのキャッシュ読取に含まれない。

## 消費候補の重複を省いた場合

申請者の手持ちと消費候補をID・呼称・個数で照合すると、集合が一致したのはAで100件、Bで98件だった。残り4件も差は各1行だった。候補はすべて手持ちを指すIDとして送られており、Aで平均176.4件、Bで29.7件あった。

11月22日の送信入力に今回の候補の圧縮と判定指示だけを適用すると、ローカルの `o200k_base` で数えた入力は1回平均でAが4,023トークン、Bが653トークン減った。変更前のローカル計数と台帳との差は、絶対値の平均でAが10.2トークン、Bが11.7トークンだった。費用の試算では出力を固定し、候補配列の差分には通常入力単価を適用した。判定指示の差分は、当時の各回でキャッシュ読取があれば読取単価、書込のみなら書込単価、どちらもなければ通常単価で計算した。各101件の計算額はAで0.4073ドル、Bで0.0677ドル減り、AとBの費用差は16.6%縮まる。指示文の変更によるデプロイ直後のキャッシュ失効は試算に含めていない。

11月22日の時点で、ダイス入力の圧縮、技能ブロックのキャッシュ、申請が指さない物品の取得経緯の省略は適用済みだった。11月23日の #405 は技能ごとの判定と製作材料の成功時消費を追加し、#413 は申請に関係する物品の成立経緯を渡し、状態を付ける対象を消費候補から外した。今回の変更は、こうした判断に必要な物品・技能・経緯と、消費できる物品の範囲を保つことを前提とする。11月22日の台帳に11月23日の変更による削減は含まれない。[入力圧縮 #287](https://github.com/KingYoSun/gestaloka/pull/287) / [取得経緯の省略 #318](https://github.com/KingYoSun/gestaloka/pull/318) / [技能と製作材料 #405](https://github.com/KingYoSun/gestaloka/pull/405) / [物品の経緯と対象 #413](https://github.com/KingYoSun/gestaloka/pull/413)

## 変更前後の比較

候補が複数あり、申請者の手持ちの全品とID・表示名・個数が一致するとき、GMへの送信では `consumable: true` で手持ちの一覧を参照する。手持ちの一部だけが候補の場合や個数が異なる場合は、候補を個別に送る。送信の直前に変換するため、同じ呼出しIDで再送したときに照合する元の入力と、サーバーで消費を確定する処理は変わらない。

11月23日の `e82af8dc` と今回の変更を、同じ架空の申請で比較した。手持ちのある例では175件の手持ちと105件の保管庫明細を用意した。最初の3例では手持ち175件がそのまま候補になる。材料消費の例では手持ちの布9個から2個を材料に指定し、同時に変更する道具を候補から外した。技能習得の例は元の1案を技能ごとに分けて3件判定する。

| 架空の申請                | 元の案数 | 入力トークン実測 前 → 後 | 1案あたりの計算原価試算 前 → 後（ドル） |
| ------------------------- | -------: | -----------------------: | --------------------------------------: |
| 単発、手持ちの道具を使用  |        1 |          20,472 → 16,198 |                     0.020847 → 0.016573 |
| 独立した複数案            |        3 |          20,938 → 16,664 |                     0.007354 → 0.005930 |
| 技能習得、内部で3件を判定 |        1 |          27,947 → 23,673 |                     0.029072 → 0.024798 |
| 材料消費、変更対象を除外  |        1 |          20,713 → 20,733 |                     0.021088 → 0.021108 |
| 手持ちと技能が空          |        1 |            1,676 → 1,643 |                     0.002051 → 0.002018 |

入力は `gpt-6.1-terra` のトークン計数APIで測った。原価は全入力を通常単価として、内部判定1件あたり出力75トークンを足し、11月22日の適用単価で計算した。キャッシュ読取・書込や実際の出力長により金額は変わる。候補が手持ちと完全一致しない例では一覧の圧縮が効かず、判定指示の分だけ20トークン増えた。手持ちが空の例では候補の読み方を伝える指示が省かれて33トークン減った。

## 判定材料と確定結果の検証

送信内容を検査し、候補を展開すると変更前と同じ物品のID・表示名・個数を読めることを確かめた。別の個数を持つ候補は個別の記録で渡す。技能のキャッシュ境界、手持ちや保管庫の明細、申請が指す物品の取得経緯、対象物の成立時と現在の保持の経緯も結合試験で照合した。模擬GM応答を使う結合試験では、成功した案だけが指定した材料を指定数消費すること、状態を付ける物品自体は消費されないこと、複数案の一部が失敗しても他の案で成立した技能と材料残数が正しいことを確認した。

手持ちの品名と個数は、申請本文に名前がない物品からGMが道具や材料を選ぶ場合に必要になる。技能の本文と習得経緯、対象物の成立・保持の経緯は、技能の適用範囲や物品の使い方が成功範囲に関わる場面に必要となる。保管庫の明細を条件付きで省くと、在庫が判断材料になる申請にも影響するため、今回は同じ消費候補を再掲する部分を圧縮した。

架空の5例について、変更前後でGMの応答を各1件取得した。下表の上限は1d100で成功する出目の上限。計算原価には、この試行での入力・キャッシュ読取・書込・出力の使用量を反映した。

| 架空の申請                 | 成功上限 前 → 後        | 1案あたりの計算原価 前 → 後（ドル） |
| -------------------------- | ----------------------- | ----------------------------------: |
| 単発、手持ちの道具を使用   | 35 → 50                 |                 0.021572 → 0.017703 |
| 独立した複数案             | 65、75、55 → 65、75、50 |                 0.007644 → 0.006363 |
| 技能習得、内部で3件を判定  | 55、75、60 → 60、70、55 |                 0.032068 → 0.027864 |
| 材料消費、手持ち全部が候補 | 65 → 60                 |                 0.020902 → 0.016954 |
| 材料消費、変更対象を除外   | 55 → 55                 |                 0.020555 → 0.020866 |

技能の3件ではGMの挙げた必要材料と個数が前後で一致した。材料消費の両例で、前後とも麻布2個を選び、刻印器は選ばなかった。手持ち全部が候補の例では、応答の使用量で数えた入力が20,635から16,361トークンに減った。複数案では最初の前後比較がいずれも出力上限450トークンに達し、表では上限を両方1,200トークンにした試行を示した。同じ試行では、それぞれの版で2案目の手持ちの布1個が選ばれた。1案目には使用可能か確認できない箱も挙がった。成功上限の差には出力のばらつきも含まれる。複数案の部分成功と材料の確定は、前述の結合試験で確認した。
