# 世界確定の出力を支えた入力と、初期文脈を絞る案

2026年11月17日。前回取得した#191本番適用後の記録を用いた調査。製品の実装・設定は変更していない。

出力の根拠を追うと、シーン内の出来事・受容だけでなく、旧記述の残す部分、既存状態の開始時点、別シーンで実際に成立した応答も判断を支えていた。これらを残しながら、イベントから機械的に作れる派生グラフをモデル入力から外す案を最初に検討する価値がある。取得範囲を狭めるなら、未完了の意図を持つ主体からの作用・受容を初期供給し、周辺の主体の経路を必要時に取得する案が候補になる。

## 対象と調査方法

対象は前回と同じ1世界のシーン終了反映19件。期間は2026-11-17 04:01:46.553424〜07:43:00 JSTで、24回のモデル呼出し、4,073,398入力token、計算額7.17035975 USDの記録である。新規参加は今回の対象に含めない。

完了範囲は、19件の参照関係を集計し、そのうち最大入力、複合状態の終了、追加照会、差分が空の返答待ちの4件について、出力の根拠を原文と入力箇所から追うこととした。その結果から初期供給と追加取得の境界を提案し、保存入力だけで可能な表現の削減を測った。

保存ログにはモデル内部の注意や推論過程はない。ここでいう寄与は、出力の本文・参照・期間・判断理由を支える情報を入力中で確認できたことを指す。削除した入力を使ってモデルを再実行する介入実験は行っておらず、実際の生成に対する因果的な必要性や、最小の入力集合を証明したものではない。出力に現れない情報を「不要」とは分類していない。

19件の最終提案には、新規scriptが25件、既存関係の終了指定が50件、意図の完了が10主体、待機が9主体、次回起動が6件あった。50件の終了対象はすべて当該入力中の既存関係へ辿れた。最終提案に対応する初期文脈の現在状態・解釈は延べ2,097記述だったが、25/2,097のような比率は寄与率にならない。変更しない判断や部分変更の確認にも入力が必要である。

## 1. 最大入力では、期間と別シーンの帰結が必要だった

操作`a9aae320-2a07-4183-8461-df922db1ca5c`は580,983入力tokenを使い、追加したのはDoroの状態1件だった。

出力本文は「Doroはトイレットペーパーを全身に巻いたミイラ姿をしている。」で、期間は`72062000〜72103000`。`completedScene.events[114]`の「体中にぐるぐる巻いてミイラみたいになって戻ってきて」という出来事の終点が72062000である。一方、`initialContext[0].result.currentStates[0]`には同じ本文の状態が既にあり、その開始時点は72103000だった。シーン内の出来事が成立を、既存状態の期間が追加範囲の終点を支えている。本文だけを残して期間を省くと、同じ状態を重複して追加するか、必要な過去の区間を落とすかを判断できない。

同じ提案は、ミューズの写真を見せてもらう意図を完了とし、「パイモンが写真機の画面を差し出し、ミューズは写真を見た」と理由を返した。このシーンのevent本文には、写真を見せてほしいと頼むところまでしかない。判断を支える次の記録は、初期文脈の作用探索結果にあった。

| 入力箇所                                     | 原文と時点                                                                             | 支えた判断               |
| -------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------ |
| `initialContext[0].result.effects[121].node` | パイモンが「写真機の画面をみんなに見えるように差し出して掲げた」。72165000〜72169000。 | 相手が実際に見せたこと。 |
| `initialContext[0].result.effects[49].node`  | ミューズが「差し出された写真機の画面を嬉しそうにのぞき込んだ」。72169000〜72173000。   | 本人が実際に見たこと。   |

両者は別シーンから共有世界へ確定したeventである。現在のシーンだけに絞ると、依頼から実際の閲覧までの間が欠ける。逆に、写真に関する語がある古い出来事を何でも使えるわけでもない。本人の今回の意図、相手の提示、本人の閲覧の順序を確かめる必要がある。

この事例は「出力が1状態だから、1状態分の入力で足りる」という見方を支持しない。状態の追加と意図の処遇は、それぞれ異なる入力を使う。

## 2. 古い複合状態は、終了後に残す内容の根拠だった

操作`ae770b9a-1a30-4723-8a07-38d4fbe9c7e6`では、ぶーちゃんの姿勢に関する旧状態を終了し、3件の状態を追加した。

新しい姿勢の根拠は`completedScene.events[11]`の「体を丸めたまま目を閉じ、うとうとと静かに息を立ててまどろんだ」だった。しかし、出力に残った毛色や周囲の条件は、この出来事にはない。

旧記述の全文には、変わった姿勢と、残る毛色・周囲・反応可能性が混在していた。新しい姿勢だけを見て旧状態を閉じると、残すべき内容まで失う。古い時点の記述も現にこの出力の根拠になっており、直近N件や一定時間内だけを供給する案は、この事例に適さない。

## 3. 空の差分でも、受容と未完了の判断があった

操作`782103d8-32a5-41a8-8d18-799bc6330d67`の追加差分は空だったが、ミューズを`deferredIntentions`へ保持している。

入力の意図は「ミチコ、僕にもお手伝いできることある？」という問い。`completedScene.events[0].receipts[1]`には、ミチコが「顔を向けて尋ねられた」と受容した記録がある。その後のeventは返答を待つ描写で、最後の`events[22]`も「返答を待った」で終わる。全23件のevent本文には、ミチコがこの問いへ答えた出来事はない。

出力は「ミューズの問いかけと両者の受容を保存し、ミチコの返答待ちを継続する」としている。質問の到達だけを完了にせず、入力の意図、受容先、後続の成立範囲を照合した判断である。77件の現在状態・解釈すべての寄与を確認できたわけではないが、空差分を判定省略の条件にはできない。

待つ描写が何度も出ることと、すべて同じ意味であることも区別する。今回は重複する描写の要約・間引きを削減試作へ含めていない。

## 4. 追加照会は、新情報の作成以外にも使われていた可能性がある

操作`fc17aed7-b4c6-466e-9138-700236f160d0`は写真機をnode照会し、既にある写真と機能の11記述を取得した。最終提案ではパイモン、Doro、ミチコの解釈3件を追加し、写真の追加はなかった。

パイモンの「明朝9時の豆畑見学と、みんなでの星見を楽しみにしている」は、`completedScene.events[63]`の「朝9時、忘れないぞ！星見のお話も楽しみだな」に対応する。Doroの分け合いたいという解釈は`events[93]`の「お茶会で一緒に食べよう！」と`events[101]`の「パイモンにも分けるよ！」、ミチコの帰路は`events[95]`の「お茶会の支度をするため家へと向かって歩き出した」に対応する。

写真機の照会結果には、以前の反映で作られた「笑顔でポーズを取るねぎとろの写真」や「集合写真」が含まれる。この照会が重複追加を避ける確認に使われた可能性はあるが、出力の理由には明示されていない。確認できたのは、モデル自身が照会を選び、その結果を受けた後で写真を追加しなかったことまでである。これを不要な照会と断定することも、必要だったと証明することもできない。

## 絞り方の候補

上の追跡結果から、初期供給と追加取得の境界は次のように考える。

| 情報                                                        | 初期供給の候補                                                   | 判断の理由                                                                                       |
| ----------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| シーンの出来事・受容と、今回処遇する意図                    | 本文、主体・受け手、参照、時点を保つ。                           | 成立と試み、実際の受容、完了と待ちを分ける根拠。event本文だけにすると受け手の情報が落ちる。      |
| 参加者・状態主体の現在状態と解釈、背景の根拠の現在版        | 今回の試作では全文・期間・参照先を維持する。                     | 複合状態の残す部分、既存期間への接続を確認するため。関連記述だけへ絞る規則は今回確定していない。 |
| 未完了の意図を持つ主体・操作主体へ届く作用と、その上流      | 初期供給する。今回の要求区間を維持し、多段経路も残す。           | 別シーンの応答・受容が処遇の判断に寄与したため。                                                 |
| その他の参加者・受け手から展開する作用経路                  | 初期供給を保留し、必要時に取得する案を比較する。                 | 初期の探索起点を減らす候補。後から必要になる経路は残し、未取得を不存在にしない。                 |
| イベントから機械的に作られるanchorのevent/happen/effect/see | 実行側で確定へ含め、モデルへ同じ派生構造を重ねて渡す部分を省く。 | 元のイベント・受容を保持すれば、保存するグラフを再構築できる。                                   |

作用の初期起点を、`request.intentions[].actorId`と`controlledActorId`へ絞る案をローカルで組み立てた。この規則は出力を見ずに決められる。状態・解釈、背景の根拠、シーンの全event・受容、操作主体の区別はそのまま残し、その他の作用群は未取得であることを示す。必要な経路は既存のqueryで取得する想定である。

最大入力の事例では、この案でも上記の写真の提示・閲覧、全event、意図、現在状態・解釈が残ることを照合した。ただし、4事例の引用を保持できたことだけでは、ほかの判断材料まで十分とはいえない。最終提案に現れた主体だけを後付けで選ぶ方法も、実際の初期供給の規則には使っていない。

必要時の照会へ移すとモデル呼出しが増える場合がある。絞った最初の要求の大きさだけで採用せず、追加取得・修正・競合後の再生成を含む合計費用と、提示される意味への影響を比較する必要がある。

最大入力の1件は、Aで1,195,942文字から733,852文字、Bで703,991文字、Cで586,201文字になった。情報の取得範囲を変えないAだけでも大きな差があり、こちらを先に試す根拠になる。Bの追加効果は合計で約2.25ポイントで、一部の小さい要求は共有表の分だけ増えた。保守するコード量を増やしてまでBを導入する必要性は、別に比較したい。

## 提案と検討の限界

最初の候補はAである。出来事・受容、旧記述、期間、別シーンの作用を保持したまま、同じ内容から作れるグラフの重複供給を減らせる。保存するanchor、同一性、履歴、競合検査は実行側に残す。

次の候補はCの初期探索起点の縮小である。主体の全過去を一律に渡す代わりに、今回処遇する意図から作用・受容へ辿り、周辺の起点は必要時に開く。ただし、今回の調査はこの案の十分性を証明していない。現在状態・解釈まで同じ規則で削ること、古い記述を時点や件数で切ること、出力に出なかった情報を削ることは、今回の根拠からは提案しない。

本番への接続・書込み、追加のモデル呼出しは行っていない。ローカルの保存JSONの分析と送信形式の投影だけであり、製品の入力範囲は変えていない。物語品質の改善も主張しない。実装の採用へ進む場合は、今回保持した根拠を使えるかに加え、シーン全提示の状況理解・関係・選択の意味を引用して比較し、追加照会を含めた実費を測る必要がある。特定の出力の再現や世界状態への正確な追従を、物語品質の成功条件にはしない。

原記録のSHA-256は前回と同じ`337a5eb6246c67b3cbba87c025d0ead68a64feecda44b7f587ec29a8c9f73952`。10件の根拠対応、原文の正確な引用、入力内のパス、集計と投影結果は同名JSONに保存した。全パスの解決と引用の一致を検証した。分析スクリプト、4事例の抽出、投影した入力は`artifacts/investigations/input-contribution-2026-11-17/`に保存し、原入力はGit管理へ追加していない。
