# #308 設計図の試遊レポート

2026年11月21日。専用の PostgreSQL と Neo4j を立ち上げ、架空の村、役割を分けたプレイヤー、試遊用の材料と銅貨を用意した。着工判定の実測、軽量botによる再現、競合などを再現する結合試験をこの環境で行った。[実装方針](../adr/ADR-074-blueprint-quests.md)

## 着工判定の費用

桟橋を兼ねる広場の空き区画に、一人用の売店を建てる計画を Claude Sonnet 5.5 で審査した。屋台組立材二組を消費し、金槌を使って建築する。焼き菓子を二つ置き、一つを銅貨二枚と交換する。GMは村の木工と通貨、港番の同意、建屋の規模と材料を理由に採用した。

| 記録した項目       | 採用された申請1件 |
| ------------------ | ----------------: |
| GMの判定           |               1回 |
| 入力トークン       |               681 |
| 出力トークン       |               253 |
| 費用台帳の計上額   |      0.003892 USD |
| 費用台帳の経過時間 |           3.649秒 |
| 申請者の日次SP     |          100 → 99 |

計上額は、入力100万トークンあたり2 USD、出力100万トークンあたり10 USDの設定による。測定した申請ではキャッシュの命中と書き込みは0だった。費用と時間はこの申請1件の値で、世界の前提や申請文、モデル設定によって変わる。

結合試験では、同意前に着工を求めた操作はGMを呼ばず、採用と差し戻しのそれぞれで1 SPを使った。採用済みの要求IDを再送すると記録済みの判定が返り、残量は99 SPのままだった。採用後の材料提供、取り下げ、進捗照会、建築と開店で追加のGM呼び出しとSP消費はなかった。

## 軽量botによる再現

Gemini 3.8 Flash に、二軒目を開くという目標、配布CLIのガイド、CLIの応答を渡した。原案者の介助なしで公開テンプレートを選び、本人が店主の設計図を申請し、建築・開店まで進めた。この試遊のGMには結合試験用の応答を使い、プレイヤー側の操作選択を実モデルで試した。

二軒目の記録には、一軒目と同じテンプレートID・原案者・発祥の世界と、二軒目の発案者・協力者が残った。別のプレイヤーが広場から初めてその店に入り、店主が退出した後に購入できた。原案者への通知は同じ公開操作を繰り返しても一度だった。

進行と再送の検証は、専用DBで `tests/integration/bot-play.test.ts` の結合試験91件を実行した。

## MCP作成から二軒目の購入までの通し検証

2026年11月21日。最新の作業ツリーからサーバーとCLIをビルドし、専用のPostgreSQLとNeo4jに架空の村を作った。管理者は試験用の認可を使い、MCP SDKから `blueprints_create` で「焼き菓子の売店を建てて開く」の下書きを作った。同じ要求を再送すると同じIDが返った。原案者が下書きのIDで一軒目を開いた後、`blueprints_publish` で同じIDの版を隔離環境内に公開した。建築にはテンプレートで指定した屋台組立材一式を使った。

二軒目では、Gemini 3.8 Flashに開店の目標、配布CLIのガイド、各操作の応答を渡した。botは原案者の介助なしで、自分の場所と持ち物を調べ、公開一覧から同じテンプレートを選んだ。設計図の申請と着工審査を経て、案内に従って組立材と焼き菓子を順に提供し、計6操作で開店した。両店に同じテンプレートID・発祥の世界・原案者が記録され、各店の店主と協力者も照合できた。原案者への顕彰通知は1件だった。

別の参加者が広場の周囲検索で二軒目への経路を見つけ、初めて入店した。店主のセッションが終了し、店主が店内にいない状態で、客は公開交換を使って焼き菓子1個を銅貨2枚で購入した。店の在庫は2個から1個に減り、売上は銅貨2枚になった。客の銅貨は6枚から4枚に減り、焼き菓子が1個増えた。

着工は両店とも実モデルのClaude Sonnet 5.5が1回で採用し、申請者は各1 SPを消費した。二軒目では材料提供から建築・開店までの追加GM呼び出しとSP消費は0だった。今回の試遊でプレイヤーbotを6回呼び出した費用は0.01780275 USDだった。

## 既存のパイモンの店での開店と不在販売

2026年11月21日。対象世界の共有グラフから、店の場所、据え付け済みの建屋、空き地との経路、店主の保管先登録、建築時と据え付け時の履歴、店内の備品に関わる9ノード・11関係を読み取り、専用のPostgreSQLとNeo4jで復元した。店主と客には隔離環境のアカウントを割り当て、開店に使う乾燥果実と代金、消費を検出するための予備材木3個を試遊用に追加した。

店主は通常のCLIで「既存の場所で開店」を選び、元の店を指定した。着工申請は1 SPで、GMには試験用の採用応答を使った。採用後に必要とされたのは今回の在庫2個で、提供は0 SPだった。開店後も元の場所と建屋のIDが一致し、復元した9ノード・11関係は購入後まで同じ内容だった。

開店のグラフ確定では、建築の確定、新規の存在、既存の存在の改訂はいずれも0件だった。終了した所持関係は、店主の手元から店へ移した試遊用在庫の1件だった。建築当時の記録は建材を文章で説明していたため、今回の建材消費は、開店時の確定差分と予備材木が3個のままであることから判定した。

店主は店外の空き地へ移動してセッションを終了した。初来店の客は、空き地の周囲検索で元の経路を見つけて入店し、公開交換で乾燥果実1個を銅貨2枚で購入した。購入後は店に在庫1個と売上の銅貨2枚、客に乾燥果実1個と残りの銅貨4枚があった。隔離環境での通し試験1件が合格した。
