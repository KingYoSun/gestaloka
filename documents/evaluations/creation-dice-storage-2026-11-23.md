# 生成GMに渡す保管庫の明細

生成GMに送る遠隔保管先の明細を、品名と個数に圧縮した。2026年11月22日と23日に一つの本番世界で保存した入力を使い、消費候補の圧縮を含む `7f7f926c` と比較した。本番ログは読み取り、実GMへの送信と隔離DBでの試遊には架空の申請を使った。[消費候補の調査](creation-dice-input-2026-11-23.md)

## 送信する在庫

保管先のIDと呼称、現地の在庫、申請がID・短縮ID・呼称で指す保管先や品の明細を渡す。その他の遠隔在庫は元の行順のまま、ID・取得経緯・成立時点の欄を空にし、品名と個数を渡す。在庫確認で品名が指定されていない場合も、GMは何が保管されているか読める。時間をかける取り寄せ、所在変更を伴う申請、ダイスを振らない差分が混ざる複数案、直接の現在地が不明な場合は全明細を渡す。

圧縮は生成判定の送信時に行う。技能のキャッシュ境界までのテキストは前後で一致する。再送照合には保存済みの元入力を使い、同じ呼出しIDの結果を再利用する。現在地の判定は製作材料の確認と同じ直接所在を使う。試算は送信テキストと費用を対象とし、保管庫を読むDB処理は従来のまま測定の範囲外とした。

## 隔離環境での入力計測

本番ログで観測した手持ちや保管庫の規模をもとに架空の申請を作った。同じ状態と申請を変更前後のフォーマッタに通し、`gpt-6.1-terra` の入力トークン計数APIを使った。時間指定と所在不明の例では入力が前後で一致した。

| 架空の申請                         | 入力トークン 前 → 後 |

| 手持ちの道具で訓練、遠隔に78品     |      21,994 → 19,822 |
| 技能の発展、対象物に成立・保持経緯 |      22,527 → 20,355 |
| 現地材料と同名の遠隔在庫           |        7,448 → 7,054 |
| 遠隔保管先を明示                   |      21,717 → 20,279 |

| 現地材料を使う独立した3案          |        7,980 → 7,614 |
| 遠隔品を短縮IDで明示               |        7,463 → 7,097 |

## 本番ログを使った費用試算

生成GMの保存入力1,345件で当時の送信テキストとキャッシュ境界を再現した。場所は所在の確定レシートから復元し、保存入力にある申請者の所在の参照先と全件で照合した。待ち時間がある申請と、元の案の一部が抽選されなかった可能性を判別できない申請は、明細をそのまま送ったものとして算定した。

変更前の原価は、保存入力に消費候補を圧縮する #421 を当てはめた試算である。変更後の入力トークンは `o200k_base` で数え、キャッシュ境界の後ろの増減分に当時の通常入力単価を適用した。キャッシュ読取・書込と出力は当時の値を使った。

| 対象期間（日本時間） | 呼出し数 | 圧縮した呼出し数 | 入力削減（トークン） | 計算原価 前 → 後（ドル） | 削減率 |
| -------------------- | -------: | ---------------: | -------------------: | -----------------------: | -----: |
| 11月22日 全日        |      487 |              194 |              231,013 |        5.19192 → 4.96091 |  4.45% |
| 11月23日 0時〜19時   |      858 |              328 |              421,476 |        6.12779 → 5.70632 |  6.88% |
| 合計                 |    1,345 |              522 |              652,489 |      11.31971 → 10.66722 |  5.76% |

2026年11月22日のA/Bでは、Aが2.15615ドルから1.97931ドル（8.20%減）、Bが0.44733ドルから0.42700ドル（4.55%減）となる。元案数を復元できた申請の1案あたりの原価は、22日が501案で0.010110ドルから0.009654ドル、23日が838案で0.006966ドルから0.006478ドルだった。元案数が不明な呼び出しは、各日14件と38件を1案あたりの計算から外した。

送信準備時のDBの状態そのものは保存されていない。予約直前10秒に所在が変わった例を追加で据え置くと、削減見込みは合計0.60173ドルだった。30件では圧縮する行が少なく、注記が加わった分だけ入力が増えた。

## 試遊で観測した影響

当初は品名と個数を別欄にまとめた。訓練用の装具に状態を付ける例では、手持ちの道具と対象の状態・成立経緯を維持していても、成功上限が4組すべてで15〜40ポイント下がった。送信内容が一致した所在不明の例でも、成功上限は45・65から40・55に動いた。

元の行順と列構成を保つ形式で、装具の例を3組比較した。成功上限は75→80、65→70、70→80で、どの応答も同じ装具を対象に選んだ。別欄にまとめた試行で続いた低下は、この3組では再現しなかった。

現地と遠隔に同じ品名の在庫がある製作では、両版とも麻布2個を選んだ。成功上限は80から65に動き、計算原価は約0.00385ドルから0.00337ドルに下がった。実GM応答を隔離DBで適用すると、現地の在庫が9個から7個に減り、遠隔の在庫は4個のままだった。

実GMに独立した3案を渡した試行では、現地に9個しかない材料を12個使う案の成功上限を両版とも0とした。技能発展の1組では成功上限が68から65となった。変更後の応答は在庫にない材料名を挙げたため、この例はGMの応答までを確認した。

当初の別欄形式で品名を明示しない製作を4組比較すると、成功上限は変更前が15〜45、変更後が10〜55だった。いずれもGMが「織物」など在庫の呼称に一致しない材料を挙げたため、この試行では製作成立まで確認できなかった。各試行で観測した成功上限から、個々の申請での影響を一般化することはできない。

隔離DBでは5ケースを変更前後で実行し、固定した出目で確定を比較した。遠隔品を現地の消費材料として指定した場合は材料不足となった。3案では必要な在庫が足りる案だけが成立し、材料は成功した案の分だけ減った。対象物への状態付与では、成立・保持の経緯が判定に届き、対象物を残したまま状態が確定した。同じ要求を再送しても消費は重ならなかった。
