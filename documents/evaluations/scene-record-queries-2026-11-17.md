# シーン進行の初期情報と追加照会の比較

2026年11月17日。[ADR-045](../adr/ADR-045-scene-record-queries.md) の実装検証。

## 対象と方法

高額だった3シーンから保存入力を9件固定し、同じ運用設定版2の下位モデルで、従来の全文入力と今回の初期入力を比較した。過去の発言を確かめる追加入力を各シーンに1件ずつ置き、モデル自身による履歴・配送本文の照会も検証した。追加3件はローカルの比較用入力で、実際の過去のプレイヤー入力とは分けている。

初期入力の組立てと照会は製品の `scenePlayContext` と `readSceneRecords`、生成と料金計算は製品の `LlmClient` を使った。生成は独立したローカル環境で行い、本番のプレイや世界編集は行っていない。比較対象は進行生成の1段階を照会・形式修復が終わるまでであり、自動継続を含むシーン全期間や終了時の世界反映の費用ではない。

## 費用

| 対象              |         従来 | 初期情報＋照会 |    減少率 |
| ----------------- | -----------: | -------------: | --------: |
| 保存入力9件       | $0.125683088 |   $0.053151620 |     57.7% |
| 過去資料の照会3件 | $0.090509780 |   $0.041748600 |     53.9% |
| 合計12件          | $0.216192868 |   $0.094900220 | **56.1%** |

モデル呼び出しは両方とも15回。従来側は12件の初回生成と修復3回、変更後は12件の初回生成と追加照会後の生成3回だった。変更後の3例では、モデルが人物と話題を選び、実際に照会応答を読んでから進行を返した。照会・修復を含む入力トークンは2,519,836→884,578。料金は保存された適用単価による計算額で、プロバイダー請求書ではない。

従来側の修復費用を除いた $0.188661772 と比べても、変更後の全費用は49.7%低かった。ただし、キャッシュの効き方によって12件中2件では個別費用が増えた。各入力で必ず安くなることや、本番全体で同じ減少率になることは保証しない。

試行・再検証を含む今回の生成費用は $0.786534992。前の比較費用と合わせて $1.396610326 で、既存の上限2ドル以内に収まった。未精算の呼び出しはない。実験の出力上限は両条件で16,384トークンに揃えた。

## 意味と選択の確認

物語の新情報を増やすことや、台詞・NPCの行動・結末の一致を合格条件にしていない。保存されたシーン全体を比較元とし、今回の提示が状況理解、人物や関係の解釈、次の選択をどう支えるかを原文で照合した。

保存入力9件の対応は次のとおり。IDは元のモデル要求の先頭部分で、全文と生成結果はローカルの検証記録に保存している。

| 要求       | 保持した意味                                                               |
| ---------- | -------------------------------------------------------------------------- |
| `57c32db0` | 初対面の挨拶を同じ人物へ届け、相手の返答や協力を代作しない。               |
| `02ac62bf` | 朝の畑の予定への楽しみを伝え、別の人物の未完了の問いを完了に変えない。     |
| `08b1656f` | 休んでいる相手への声かけとして届き、本人の姿と同一性を保つ。               |
| `a1072824` | 出身地の説明と家への誘いとして届き、相手が訪問を決めたことにはしない。     |
| `2ec5ac01` | 写真への参加の申し出と、その場で別に残っている返答待ちを区別する。         |
| `4ea349cd` | 明朝の予定を話す場面のまま、現在を翌朝や畑への到着に進めない。             |
| `55ee78d2` | 本人が知っている住まいと自己紹介を保ち、別の人物を作り直さない。           |
| `31cf3460` | 「見てきたら伝える」という将来の申し出を、調査済みや世話役判明へ変えない。 |
| `ef2be9d2` | 姿への驚きと写真を見せてほしい依頼を分け、相手の返答を待つ余地を保つ。     |

追加の照会例では、次の差を確認した。

- 持ち寄り品の例では、変更後は過去の自己発言を照会し、「甘い半分はみんなで分けようね」と述べていたオレンジの話へ戻った。準備を考える選択は本人に残り、物を実際に受け渡したことにはしていない。
- 依頼品の例では、原文の「家の外壁を塗る紫の塗料」と、別の本人の知識にあった鉄条網の計画を分けた。待ち合わせは「家の前」で、その後の行き先が豆畑であることも読み戻せた。「畑で集合」と一つに丸めると次の選択が変わるため、この区別を確認した。
- 星の話の例では、履歴と受信を照会して「シリウスやオリオン座」という以前の言葉へ戻った。変更後の「ご都合のよい夜を教えてくださいね」は新しい誘いであり、相手が日程に同意したことにはしていない。昔の言葉の再掲を新しい知識として加点していない。

これらは有限の場面の手動確認であり、あらゆる世界の意味判断を証明するものではない。原文が読み戻せることだけを、生成される物語の意味が保たれる証明とは扱っていない。

## 実行経路と保持

実DBの検証では、初期から省いた古い約束と配送本文を世界照会と同じqueryに混ぜて取得し、生成途中で中断した。新しい配送を追加してから再開しても、照会結果は最初の要求時点の原文のままで、表示済み履歴と選択済み入力を保持した。

世界更新で増えた所有・関係の参照を落とさないよう、現在のnode資料は関係集合ごと初期に残した。新しい未完了の意図は元の出来事を参照する。起点のない旧継続は、最後の配送を元の問いと推定せず当人の履歴を残す。同時点の受信もID順で一つへ絞らない。これらを単体・結合テストで固定した。

生の入力・応答・追加照会・費用・失敗を含む試行記録は、非コミットの `artifacts/investigations/scene-context-implementation-2026-11-17/` に保存した。`validation-summary.json` は採用した生成結果と現行の初期入力の一致、料金内訳、実験予算を再計算している。
