# 継続判定を形式修復で反転させない

2026年11月17日。キッス、ミチコ、メイリー、ムジーナの保存シーンを使ったローカル検証。本番の終了済みシーンや履歴は変更していない。

## 原因と修正

シーン`ecd0f47b-d0ec-4079-9bf9-f247b8f39806`では、01:31:49 JSTに開始した呼出し`8bd618d8-6e81-4ff7-a534-07abe647ad82`が`concluded:false`と、キッスの未実行部分を返した。

> 分かれ口の村長のところへ向かい、ナギのことやピザ材料について挨拶と質問をする

当時のスキーマは`true`だけを受理したため、`Invalid input: expected true`が形式エラーとして送られた。次の呼出し`fe8698bf-363b-403d-9cc7-6f5929c38c81`は`concluded:true`へ変更し、キッスの判断も`decide`へ変更した。共有シーンは終了処理へ入り、受理済みの入力を処理した後、01:35:59にリザルトになった。

修正は次の契約に絞った。

- 新しい出力と旧保存出力の両方で、`false`・省略は継続、`true`は区切りとして受理する。
- 同じ要求の形式修復は、修復履歴にある最初の読取可能なシーン応答の終了判定を保持する。新しい保存フィールドや別の判断エンジンは追加せず、既存のWorkのメッセージから読む。
- 保持する判定を修復用スキーマへ反映し、実行側でも反転を拒否する。参照の照会は既存の処理を使い、形式修復を局所状況の再生成へ切り替えない。
- モデルへ渡す契約は、最後に指定された`responseSchema`を使う。テキストでスキーマを渡す場合も古いスキーマを重ねず、構造化出力の場合も最新の契約を選ぶ。保存済み要求の原文と確定済み応答は書き換えない。

`true`による区切り、明示的な終了、10往復での終了提案は維持する。依存状態の競合による新しい文脈からの解決と、同じ出力の形式修復を区別する。通常プレイへの追加点検・採点・生成呼出しはない。

## 保存記録による実行

当時のモデル入力・出力、32件の発生済み履歴、四人の選択済み入力、背景、所在地、反応機会を保存し、隔離したローカルDBへ判定待ちの状態を再構成した。実行側のシーンID・世界ID・実行IDを隔離し、人物と出来事への参照、入力の原文は保持した。225ノードの同一性と入力に載っていた所在地・参照を用意した再構成であり、当時の世界全体のバックアップ復元ではない。

通常の`WorldScenes.tick`、スキーマ検証、形式修復、状態確定と共有シーン制御を実行した。保存された応答はローカルの検証用キャッシュへ登録し、新しく必要になった形式修復だけを`gemini-3.8-flash`、reasoning effort=`low`で実行した。検証用キャッシュは新規生成やその費用に数えていない。

| 条件                                              | 実際の確認                                                                             |
| ------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 元の`false`出力                                   | 追加モデル呼出しなしで受理。未実行部分を保持し、リザルトにならない                     |
| 旧修復履歴と保存済みの`true`応答から再開          | 履歴中の元の`false`を読み、反転した応答を拒否。下位モデルによる修復結果も`false`で受理 |
| 元の`false`応答の所在地配列だけを空にした形式不備 | 下位モデルが所在地を修正し、`false`とキッスの未実行部分を保持                          |

いずれも開始時の往復数9から10へ進み、`state=active`、`flow=voting`、`end_reason=null`となった。終了提案は1件で、リザルトは生成されていない。元の32件の履歴は変更されず、同じ発生を再表示していない。

10往復時の投票待ちは、この不具合とは独立した既存の操作である。今回の確認は「永久に終了しない」ことを成功条件にせず、形式修復が元の継続判定を終了へ変えないことと、通常の選択へ引き継ぐことを確認した。

## 提示と限界

元の応答でも修復後の応答でも、四人が言葉を交わして歩き出す描写はあるが、村長への到着・挨拶・質問・回答が新しく達成されたことにはしていない。キッスの未実行部分は前掲の原文のまま残った。新しい材料情報や特定の人物の協力を期待値にはしなかった。

この修正で変わったのは、同じ提示の後に未完了のまま終了することと、未実行部分を保持して続行・終了を選べることの違いである。物語全体の新情報が増えた、自由入力全般の完遂率が上がった、という検証ではない。

原文、入力のハッシュ、修復のフィードバック、モデル出力、状態の前後、費用・時刻は[保存資料](conclusion-preservation-2026-11-17.json)に収録した。完全な取得原本と各試行はローカルの`artifacts/conclusion-preservation-20261117/`に保存し、過去の試行を上書きしていない。最初の復元試行は検証用の同一性の重複で失敗し、隔離IDを分離して再構成した。費用は0.182211823 USD。その後の試作確認は0.186334253 USD、0.188831862 USD。最終試行は0.181129741 USDで、時間は保存資料の`startedAt`・`finishedAt`を参照する。金額はAPI使用量と適用単価からの計算額で、プロバイダーの請求額ではない。

## 回帰試験

真偽値と省略、複数回の反転、照会を挟む修復履歴、構造化・テキスト両方のスキーマ選択を単体テストで固定した。実DBの回帰テストでは別の形式不備の修復中に保存・再開し、反転した出力を受理せず、履歴が一度だけ表示されることを確認した。シーン・LLM・保存済み要求の再利用を含む既存試験と、CIの全結合・認証・E2E・復旧試験を通してから本番反映する。
