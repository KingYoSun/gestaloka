# シーンの提示内容から物語の停滞を切り分ける検証手順

移動量の改善では、あらすじ・応答・リザルトを含むシーン全提示を読み、因果・理解・関係・選択の前提がどう変わったかを主に判断する。主指標はシーン全提示の新情報数と、そのうち重要度2以上の意味単位数で、以前の提示との差と正確な引用を付ける。応答ごとの追跡も残し、合計値だけで採否を決めない。

NPCの性格・目的・認知範囲を保ち、個々のNPCが全ての問いに漏れなく答えることを一律の成功条件にしない。回答漏れ、話の逸れ、不知や拒否は、それだけで不具合とも移動とも判定せず、人物とシーンへの影響から確かめる。[ADR-028](adr/ADR-028-npc-character-and-scene-progress.md)を参照する。

## 制約と完了条件

通常プレイへ、LLM点検による改善専用のループ、候補の生成と採点による選別、点検結果に基づく再生成を追加しない。既存の実行段階の中で、必要な情報の取得・組み立て・指示・出力処理を改善する。開発時に保存記録を検品し、仮説に基づく修正と再検証を繰り返すことは、この制約と区別する。

改修は世界名、職業、人物名、身体の有無、個別の設定や固定の展開メニューへ依存させない。世界ごとの入力や期待する具体的内容は検証資料として持てるが、製品コードや共通プロンプトの分岐にしない。世界の因果とプレイヤーの選択を守り、成功や協力、新しい事件を評価のために強制しない。

着手前に、対象の入力・提示・呼出し・比較元を固定し、次を受入条件として明示する。

1. 対象シーンの全提示について、入力の目的、既知情報との差、人物の選択とその根拠を記録する。応答単位の不足や逸れも残し、回答漏れだけを問題の根拠にしない。
2. 必要な世界の事実、本人に成立する性質・認知条件、本人の知識が、当時のグラフ、取得結果、実際のモデル入力のどこに存在したかを分けて照合する。未取得を不存在と判断しない。
3. 特定した原因に対応する修正で、シーン全体の因果・理解・関係・選択前提がどう動き、利用者が得る新しい結果や判断材料がどう増えたかを引用付きで示す。内部の無駄や個別回答の網羅率だけで移動量の改善を達成したとしない。
4. 同じ原因を異なる設定でも確認し、人物の性質・認知範囲の破壊、選択の代行、秘密の漏出、根拠のない状態・確かさの変更、既出提示の重複を増やしていないことを検証する。
5. 通常プレイへ改善専用のLLM呼出しを追加せず、触った層のテストを通す。実測した費用・時間と限界も記録する。

各反復は、一つの原因仮説と、それを支持または棄却する確認までを範囲とする。反復回数だけで成功・失敗を決めず、未解決の原因を残したまま完了扱いにしない。利用者体験や互換性の変更、資源上限の見直しが必要になった場合は、AGENTS.mdの作業原則に従って判断を求める。

## シーン全体と応答ごとの分析

あらすじ、各入力への応答、リザルトを時系列で一つずつ記録する。narrative-inspectionの基準で新規性・重要度・連続性を照合し、応答判定は診断として別に残す。診断の未回答件数を、NPCへの再判断や完全回答の義務へ直結させない。

| 項目           | 照合する内容                                                                               |
| -------------- | ------------------------------------------------------------------------------------------ |
| 対象           | manifest・シーン・入力・提示・モデル呼出しのID、設定とプロンプトの版                       |
| 入力の目的     | 独立した問いや試み、制約、どこまで本人が選んだか                                           |
| 既知情報       | 初期提示と当該応答より前の提示。宣言・意図と実行結果を分ける                               |
| 人物の条件     | 定義済みの本人の性質・認知条件、観測・自己理解、既存の目的を分け、実入力への供給を確認する |
| 実際の応答     | 正確な短い引用、届いた結果、未回答の部分、先送りや復唱                                     |
| 移動の内容     | 以前と今回の違い、新しい根拠、今後の理解や判断への影響                                     |
| 内部の根拠     | 当時のグラフ、DB取得結果、各段階の実際の入力・生出力、表示までの加工                       |
| 原因と確かめ方 | 下記の分類、失われた箇所、対照となる入力、修正で変わるはずの内容                           |

入力が情報を求めている場合、「説明した」「確認した」という行為の描写だけを具体的な回答内容として数えない。一方、全項目へ答えや明示的な不知・拒否を返すことも必須にしない。返した内容、返さなかった部分、人物の選択、その後のシーンの変化を分ける。

本人が選んだ行為の未実行部分、実際の返答待ち、作用・受容の未到達は保持する。部分回答を得てプレイヤーが選び直せることを、待った結果の創作や未完了行為の完了扱いと混同しない。新情報量、重要度、応答性、原則適合は別々に記録し、単一の総合点で相殺しない。

## コンテキストと指示の切り分け

当時の入力を使い、必要な命題を次の順に追う。現在のグラフや修正後のコードから、過去にも同じ情報が渡っていたと推測しない。

1. **グラフの記録・モデル構造**：必要な現実状態、作用経路、所有、観測、解釈を表現でき、参照元から辿れるか。未記録の局所状態を具体化する責務がどこにあるか。記録がないだけで直ちにモデル構造の欠陥としない。
2. **シーン開始時などの取得クエリ**：必要な記録はグラフに存在するが、起点・関係・向き・時点・観測範囲などの条件で取得から漏れていないか。固定スナップショットでクエリを確認する。
3. **コンテキストの組み立て**：取得済みの本文が、背景要約・本人のview・意図形成・行動解決の間で落ちていないか。本人に成立する性質・認知条件と、本人が観測・理解した知識の両方を追い、前者を自覚した事実へ変換しない。知識APIへ未受容の状態を混ぜない。
4. **指示**：実際に渡った性質・認知条件・知識から、その人物に沿う選択が形成されるか。共通の完全回答や能動確認の指示が人物の選択を上書きしていないかも確認する。回答漏れだけを修正理由にせず、根拠となる入力箇所と関係する指示を対応させる。
5. **出力の処理・保存・提示**：モデルの生出力には必要な内容があり、後段で欠落・要約・状態変更が起きていないか。この場合はプロンプトの問題に置き換えない。

複数の原因がある場合は併記する。根拠が不足する場合は判別保留とし、次に確認する資料を限定する。必要な情報が入力にあったというだけで、指示が原因だと断定せず、世界内で答えられる内容と、生成側が判断すべき内容も確かめる。

## 原因に対応した修正と再検証

指示の問題では、関連する指示と矛盾する箇所を絞って変更し、同じコンテキストと入力でシーンの進行を比較する。変更した指示、期待した差、実際の引用、残った問題を記録する。未解決なら、その提示内容から次の仮説を立て直す。プロンプトだけを順番に変えて合計値が上がる案を探さない。

コンテキストの問題では、欠落箇所に応じてシーン開始時のクエリ、組み立て、記録方法を調べる。必要な命題や作用経路を現在のグラフ構造で表せない場合に、モデル構造の変更を検討する。コンテキストにない事実を、プロンプトで知っていることにしない。

修正前後では、応答ごとの選択と、それを含むシーン全体の通常進行を確認する。本人に渡した条件・知識、本人の意図、実行、受容、利用者への提示を追う。局所的な意図や内部情報が増えただけで達成とせず、シーンの提示に何が増えたのか、既知情報を言い換えただけかを再び分析する。

同じ原因が現れる別設定と、既に正常な対照例でも確かめる。動機や認知条件が異なる人物も使い、両条件に同じ定義を比較前に固定する。改修後だけ、または比較の途中で都合のよい人格を追加しない。期待値は人物名や結末を固定せず、シーンの変化の根拠、履歴の連続性、人物とプレイヤーの選択が守られることへ置く。

## 記録と採否

各試行の入力・出力・プロンプト・コンテキスト・費用・時間・失敗を保存し、過去の試行を上書きしない。自動検品の失敗と本文の問題を分け、手動検品で補った場合は評価方法の差を明示する。

採否はシーン全提示の変化と原因仮説の検証結果から決める。件数が増えても復唱や重要でない描写が増えただけなら、その限界を記す。個別の回答が増えなくても、人物や関係の理解、選択の前提、状況の因果が変わったなら、その内容と根拠を記録する。情報量で人格・認知・因果・プレイヤーの選択の破壊を相殺しない。少数回の試行を、効果がないという断定や普遍的な改善率へ広げない。

完了報告には、解消した原因、利用者へ新たに届いた内容、異なる設定での確認、維持した制約と検証結果を示す。移動量の改善が未確認なら、そのまま未達として残し、基盤修正やPRのマージだけで元の目的を達成したと扱わない。
