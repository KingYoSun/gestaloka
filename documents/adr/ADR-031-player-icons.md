# ADR-031: プレイヤー人物のアイコン

## 決定

アイコンはアカウント単位ではなく、世界に参加した人物ごとに持つ。参加生成中は参加要求のIDに対応させ、生成完了後も同じIDで設定する。既存人物は参加権限のIDを使う。画像はPostgreSQLの`world_player_icon`へ保存し、既存のDBバックアップに含める。世界内の性質・観測やLLMへの入力には追加しない。

本人の`GET /api/worlds/:id/players`と`/players/:playerId`に、人物の`name`と`icon`を追加する。`playerId`は一覧の`id`であり、生成された存在の`actorId`とは区別する。

登録・差し替え・解除には`PUT /api/worlds/:id/players/:playerId/icon`を使う。既存のログインと利用登録・BANを確認し、本人の参加要求または有効な参加権限に対応する人物だけを更新する。変更要求には`X-Gestaloka-Request: 1`を付ける。

```json
{ "image": "画像ファイルの内容をbase64で符号化した文字列" }
```

`image`はdata URLやファイル名を含まない。解除は`{"image":null}`で行う。成功時の`image`は保存済みWebPのdata URL、または`null`である。参加受付後は、生成中でも参加要求のIDを指定して登録できる。画像登録の失敗で参加や以前の画像は取り消さない。同じPUTで再試行できる。

JPEG・PNG・WebPの静止画を受け付ける。容量は5MiB以下、長辺は4096px以下とし、実データをデコードして検証する。GIF・SVG・アニメーション画像は拒否する。EXIFの向きを適用し、縦横比を保って長辺256px以下へ縮小する。小さい画像は拡大せず、付加情報を除去してWebPへ変換する。

他人のアイコンを取得する公開URLや人物検索APIは設けない。本人へ提示する受容・観測の明示的な人物参照から候補を求め、表示本文にその存在の呼称が含まれる場合に限り、`characters`として名前・存在ID・画像を添える。確定済みの出来事への観測でも、保存された本人向け受容の人物参照を使う。出来事の実行者やシーン参加者の一覧から正体を推定しない。自分が入力した行動には本人を添える。画像未設定・旧データ・画像読込失敗時は、名前と既定の人物表示を使う。

Webは参加時に選んだ画像と登録要求を人物ごとのキーでIndexedDBへ保存する。登録に失敗した場合は明示的に再試行でき、再読込時にも未完了の登録を再開する。参加と画像登録を別に保存し、画像の成否でプレイ開始を妨げない。

## 判定方法

- `tests/unit/player-icons.test.ts`で形式・容量・寸法・破損・アニメーションの拒否、縮小・向き・付加情報の除去を検証する。
- `tests/integration/player-icons.test.ts`で2ユーザーと同じ持ち主の複数人物を使い、生成中の対応、更新権限、相互の観測と匿名の受容、シーンと行動履歴、失敗後の保持・再試行・解除・旧人物を実DBで検証する。
- `tests/e2e/player-icons.spec.ts`でWeb参加、登録失敗、再読込、人物設定、API経由の更新、2ユーザーの画面表示、読込失敗の既定表示をブラウザーで検証する。

Webと共通APIを先に提供する。#124のプレイヤーCLIへの組み込みとCLI実行による相互確認は、その実装後に行う。#125全体の完了にはCLI側の検証も必要とする。
