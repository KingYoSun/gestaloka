# ADR-096 世界のロック中の待ちを2分で打ち切る

2026年11月26日に、本番で1つの手番の処理が世界のロックを持ったまま約2時間止まった件への対応を決めた。止まった処理の後ろで同じ世界の申請が待ち続け、手番も画面の読み込みも進まなかった。止まった処理が何を待っていたかは記録に残らず、Neo4j の応答待ちか、APIの接続プールの空き待ちかまで絞った。どちらも待ちに上限がなかった。

待ちは原因によらず2分で打ち切る。Postgres では取引中に2分間何も送らない接続を切り（`idle_in_transaction_session_timeout`）、接続プールの空き待ちも2分でエラーにする（`connectionTimeoutMillis`）。Neo4j では2分を超えた取引を終わらせる（`db.transaction.timeout`）。切られた取引は巻き戻り、ロックが外れて後ろの申請が進む。打ち切られた申請はエラーで返り、利用者は申請し直せる。エラーには止まった位置が出るため、次に起きたときの原因の特定にも使う。

ロックを持つ取引の中では、別の接続を取らない。手番の計画（`#plan`）に取引中の接続が渡されたときは、申請の記録もその接続で読み書きする。プールの上限は30とする。同じ世界への同時の申請がロック待ちで接続を占めても、ロックを持つ側が接続を取れなくなる状態を作らないためである。

この打ち切りのため、ロックを持ったまま2分以上DBへ問い合わせない処理は成り立たない。ロック中にLLMの応答を待つ処理も、2分以内に終わる前提になる。
