# ADR-072: 所有と保持の統合と、保管先の登録

状態: 採用。2026年11月21日のユーザー判断を記録する。[ADR-037](ADR-037-belongings-and-skills.md)の役割なしの `has`（所有）と `hold` の区別、[ADR-050](ADR-050-bot-session-play.md)の所有者による譲渡、[ADR-069](ADR-069-deferred-receipts-and-exchanges.md)の公開交換の所有条件を置き換える。

## 問題

物品の関係は、所有（役割なしの `has`）と所在（`hold`）に分かれ、操作も `transfer` と `move` に分かれていた。贈与・売買・支払いは両方を変える組み合わせとして定めていたが、プレイヤーに見える操作は部品の二つだけだった。

本番の世界では、プレイヤーがどちらか片方で「渡した」ことにしていた。代金の支払いと売買の9件は `move` だけで、所有者は払った側に残った。贈り物では、`transfer` だけで物が贈った側の手元に残った例が多かった。片方で済むという理解は、申請の添え書きから読み取れる。説明文書を足しても、名前と意味の対応はプレイヤーごとに食い違う。

所有は、物が実際にどこにあるかと独立した権利である。GESTALOKAの世界は、起きた行動と現象を積み重ねて進む。貸し借りや預かりはプレイヤー間の約束として記述に残せばよく、システムが権利として守る必要はない。

## 決定

### 持つことが、その人の物であること

- 物品の関係は、`has`（役割 `hold`）一つにする。`hold` は「その存在が持っている」ことを表し、その存在の物であることを兼ねる。一つの物品について、終了していない `hold` は同時に一つだけとする。物品への役割なしの `has`（所有）は記録せず、読まない。保存済みの `hold` を書き換えないため、役割の名前は変えない。
- 物品の移動は `move` 一つにする。`transfer` の操作、`create` の `owner`、応答の `ownership`・`owners`・`ownershipUnrecorded` はなくす。贈与・売買・支払い・貸与は、どれも `move` で表す。借りた物を返さずに持ち続けることもできる。
- `move` は、物を持っている存在が決める。人物が持つ物を奪うには、従来どおり対抗行動とダイスを使う。持っている物の中身（箱の中の物など）も、その箱を持つ存在が決める。
- 存在からの記述（`script`）への役割なしの `has` は、記録や書き付けを持つ関係として変えずに残す。

### 保管先の登録

- 家と場所だけを、人物の保管先として登録できる。登録は人物から家・場所への `has`（役割 `use`）で表す。これが、システムが明確に守る唯一の所有関係である。ペットなど、家と場所以外の存在への所有関係は持たない。
- 登録した保管先の中身は、どこからでもいつでも読める。
- 登録のない場所に物を置く・そこから拾うのは、本人の直接の滞在先が同じかどうかだけで決まる。
- 登録した保管先との出し入れは、登録した人物が同じ場所にいるときにできる。登録のない人物が物を置くには、登録した人物の受領が要る。置き手紙や置き土産のように相手が不在のときは、既存の時間差の受領で扱う。登録のない人物は、登録された保管先にある物を取り出せない。
- 家や場所の登録は `grant` で行う。誰も登録していない家・場所の登録は、新しく得る申請としてダイスで判定する。登録済みの保管先を他の人物にも分けるときは、登録した人物の受領が要る。

### 公開交換

- 公開交換は、売り手が登録した保管先で出す。品物は保管先が持つ物とし、代価は同じ保管先に入る。買い手は品物を手にする。

## 既存データの移行

本番の世界には、2026年11月21日時点で有効な関係が次のとおりあった。

| 対象                               | 件数  | 移行後                                                        |
| ---------------------------------- | ----- | ------------------------------------------------------------- |
| `hold`                             | 1,322 | 変えない（物品を持つ関係として読む）                          |
| 所有と所在が同じ存在               | 227   | 所有の関係を終了する                                          |
| 所有と所在が別の存在               | 114   | 所在を残し、所有の関係を終了する（持っている存在の物になる）  |
| 所在がなく所有だけある家           | 11    | `use` にする。すでに `use` があれば所有の関係を終了する       |
| 所在がなく所有だけあるペット       | 1     | 所有の関係を終了する                                          |
| 所在がなく所有だけあるその他の物品 | 33    | 他の関係から妥当な場所・存在を個別に判断し、その `has` にする |
| `use`                              | 26    | 変えない                                                      |
| 存在から記述への役割なしの `has`   | 30    | 変えない                                                      |

移行は、関係の有効期間を終了して張り直す管理修正で行い、過去の関係は消さない。個別に判断する33件は、移行前に一覧と判断の根拠を持ち主に示す。

持ち歩く入れ物を店の在庫置き場として使っていた人物は、公開交換を出せなくなる。その店が営まれている場所に行き来できる場所を管理修正で作り、その人物の保管先として登録する。

## 互換性

- 申請の `transfer` と `create` の `owner`、応答の所有の項目がなくなる。プレイヤーCLIの版を上げ、古い版には更新を求める。
- 旧版のサーバーへ戻すと、所有の関係を終えた物品は所有者が未登録として読まれ、`use` のない家は保管先から外れる。旧版へ戻す場合は、移行前のバックアップを使う。

## 文書

スキルと参照文書は、核の概念（持つ・保管先の登録・同じ場所）を短く書き、実際に使われている応用（売買・支払い・贈与・貸し借り・店の開き方）の書き方を厚くする。保管先の登録だけがシステムに守られる所有であることを強調する。

## 受入条件と判定

| 対象         | 期待結果                                                                                                                                                             | 判定方法               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 受け渡し     | `move` 一つで、物はそれを受け取った存在の物になり、所有だけ・所在だけが残る状態ができない                                                                            | 結合試験               |
| 売買         | 品物と代価の `move` を1件の申請にまとめると、相手の受領で両方が同時に成立する                                                                                        | 結合試験               |
| 箱の中身     | 箱を持つ人物は、場所を問わず箱へ出し入れでき、箱を持たない人物はできない                                                                                             | 結合試験               |
| 保管先       | 登録した人物は、離れた場所から中身を読め、同じ場所にいるときだけ出し入れできる。登録のない人物は取り出せず、置くには登録した人物の受領（不在なら時間差の受領）が要る | 結合試験               |
| 公開交換     | 登録した保管先で出せ、品物は買い手の手元、代価は同じ保管先に入る                                                                                                     | 結合試験               |
| なくした項目 | `transfer`・`owner`・`ownership`・`owners`・`ownershipUnrecorded` が契約と応答に残っていない                                                                         | 型検査と契約の生成照合 |
| 移行         | 上の表の各分類について、移行後に存在から存在への役割なしの `has`（所有の関係）が残っていない                                                                         | 本番グラフの読み取り   |
| 文書         | スキルに、持つこと・保管先の登録・同じ場所の判定と、売買・支払い・贈与・貸し借り・店の書き方がある                                                                   | 配布文書の照合         |
