# ADR-035: シーンの生成内容を同じ要求内で修正する

2026年11月9日。ユーザーは、生成内容の不備を自動修正し、再開操作を不要にする方針を採用した。

## 決定

背景準備、NPCの意図形成、行動解決、リザルトで、JSON・型・参照・シーン構造の不備や取得済み応答の未完了を検出したら、同じ要求内で修正する。最後に保存した進捗へ戻り、不採用の出力と検査結果を次の生成へ渡す。表示済みの履歴や本人の入力は作り直さない。内容を採点するLLM点検は追加しない。

修正には新しいcall IDを使い、元の応答生成の費用・呼出し上限とモデル設定版を引き継ぐ。送信結果が未確定の要求、予算不足、呼出し上限、運用停止、権限失効、モデルが必要条件の不足を明示した停止は、自動再送へ変換しない。保存済みの生成保留には従来の再開操作を残す。

同日の追加判断により、全員切断による休止は参加者の再接続で自動復帰する。切断が10分続けば成立済みの内容を確定して終了する。期限はDBとキューに保存し、再接続で取り消す。再び全員切断した時点から10分を数え直す。切断時刻のない旧版の休止は、新版の起動時から数える。投票や人間の入力待ちは復帰後も維持し、別の原因の保留を再接続で解除しない。

## 完了条件と判定方法

1. 共有シーンは全員続行後も10往復ごとに終了投票を繰り返す。実DBとCLIで20・30往復後の投票、投票中の生成停止、続行後の反応機会、保留通知がないことを確認する。終了・混在・期限切れ・人間の割り込みは既存の検証を通す。
2. 各生成段階の不備は、再開操作なしで修正する。実DBでJSON・型・未完了応答を投入し、背景・意図・行動・リザルトが進むことを確認する。既存参照の不備も同じ経路で検証する。
3. 修正と同じ要求の再送で履歴を重複させず、修正callも元の上限へ通算する。実DBで表示済みの出来事、保存済み応答、呼出し台帳を照合し、上限後に新たな送信がないことを確認する。

4. 接続者不在による休止は、開始者以外の参加者の再接続でも自動復帰する。実DBとCLIで同じ反応機会への復帰、再接続での期限取り消しと数え直し、10分直前の休止と期限到達時の終了、期限処理の再送、別の原因の保留を維持することを確認する。

これは進行を妨げる生成不備への対応であり、物語の意味的新規性や重要度が改善したという判定ではない。
