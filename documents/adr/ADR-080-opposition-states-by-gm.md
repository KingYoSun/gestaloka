# ADR-080 対抗行動が成功したとき、GMが人物に残る状態を決める

状態: 採用。2026年11月23日のユーザー判断を記録する。申請者が変更に書いた相手の状態の扱いは、[ADR-085](ADR-085-opposition-states-only-from-gm.md)で改めた。対抗ダイスでGMが返す内容（[ADR-064](ADR-064-instant-npc-death-and-drops.md)、[ADR-065](ADR-065-person-death-penalty.md)、[ADR-066](ADR-066-item-count-and-consumption.md)）に、人物の状態を加える。

## 問題

人物への対抗行動では、GMは申請の文面と変更の両方を読んで成功率を決める。成功したときに確定するのは、申請者が組んだ変更だけである。文面が意味する結果を申請者が変更に書かなければ、成功しても対象には何も残らない。

対象世界の記録（2026年11月23日）では、プレイヤーが武器で相手を負傷させる対抗行動を申請した。変更に入っていたのは、武器を相手へ移す操作だけだった。ダイスは成功し、武器は相手の持ち物になったが、相手の状態は何も変わらなかった。直後の発言から、申請者は攻撃が命中したと受け取っており、意図した結果と記録が食い違った。

この食い違いは、行動の種類や世界の設定によらず起きる。成功率は文面で決まるのに、結果の記録は申請者の書き方に任されているためである。

## 決定

- **方針を改める。** これまでGMは、ダイスの設定のほかに変更を作らないとしてきた。今後は、ダイスが成功したときに起きる変化に限って、GMが決めてよい。死亡（`fatal`）、消費（`consumes`）、申請者が中身を委ねた技能・物品の本文（`decided`、[ADR-059](ADR-059-creation-dice.md)）は既にこの形で、ここへ人物の状態を加える。成否、出目、物語はこれまでどおりGMが作らない。
- **GMは、成功したときに人物へ残る状態を返す。** 受領を経ない対抗行動で、作用を受ける同席中のプレイヤーとユニークNPCを候補（`affected`）として渡す。GMは、候補ごとに変化後の状態を一文で `states:[{id,text}]` に返す。行為者や経緯は書かず、後からその人物だけを調べた人が読める状態にする。残る変化がなければ空にする。
- **成功した場合だけ記録する。** ダイスが成功すると、返された状態を、対抗行動の変更と同じ確定で対象の人物の `status` として記録する。失敗すれば記録しない。候補にないIDの状態は捨てる。
- **死亡判定の設定とは独立させる。** 候補は死亡判定が無効な世界でも渡す。死亡の候補（`mortal`）と条件文の扱いは変えない。
- 出現個体への作用と、出現個体・NPCの外界への作用は、申請側が結果の状態を書く今の形（`effect.state`）のままとする。

応答の `outcome.setting.states` で、申請者は記録された状態を読める。

## 受入条件と判定

特定の行動や結末は期待値にしない。

| 対象         | 期待結果                                                                             | 判定方法       |
| ------------ | ------------------------------------------------------------------------------------ | -------------- |
| 候補         | 作用を受ける同席中の人物が `affected` としてGMへ渡る。死亡判定が無効な世界でも渡る   | 結合試験       |
| 成功時の記録 | GMが返した状態が、対象の人物の状態として残り、応答の `outcome.setting.states` に入る | 結合試験       |
| 候補外       | 候補にない人物への状態は記録されない                                                 | 結合試験       |
| 文書         | ダイスの解説に、GMが成功時に決めること（消費・死亡・人物の状態）を書く               | 配布文書の照合 |

## 影響

- 対抗行動の応答に `outcome.setting.states` が増える。既存の項目は変わらない。
- 過去の対抗行動の結果は変えない。
- プレイヤーCLIの解説が変わるため、CLIの版を上げる。
