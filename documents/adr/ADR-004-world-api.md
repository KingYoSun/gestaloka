# ADR-004: 構築操作・公開知識・進捗配信の境界

状態: 採用。2026-10-19。

## 今回の完了範囲

Issue #31のうち、ローカルブラウザーの識別、世界ごとの操作権、構築受付とジョブ投入、再送、管理記録と村民の知識の取得、SSEの保存・再送を接続する。実DBと実HTTPで、別主体の拒否、並行再送、公開情報の分離、履歴ページ、cursorの範囲、権限失効を検証する。人間の自由記述行動と画面は次の実装範囲である。

## ローカルの識別と操作権

初回の同一オリジン操作でランダムなCookieを発行し、PostgreSQLにはハッシュと主体IDを保存する。CookieはHttpOnly・SameSite=Strictとし、ブラウザーを開き直したときも同じ主体を復元する。HTTPSではSecureを付ける。現時点の起動範囲はループバックで、本番の認証製品を選定したものではない。

世界の作成者へ管理権を登録する。別の村民が成立した後、その同じ主体へ操作対象の割当を登録する。要求本文のactorIdや自己申告のロールは権限の根拠にしない。Cookieを持たない要求は401、利用できない世界は404で拒否する。変更操作は専用ヘッダーとOriginを確認し、異なるオリジンからのブラウザー操作を拒否する。認証済みの応答はキャッシュへ残さない。

このローカル方式はCookieを保持するブラウザーでの再開を対象とする。別ブラウザーへのログインや本番公開は、この方式で実現したとは扱わない。CLIで作った世界へブラウザーの権限を自動付与しない。

## 受付と再送

要求ID、主体、入力のハッシュ、受付結果をPostgreSQLへ保存する。構築記録、管理権、pg-bossへの投入、受付結果は同じ短いトランザクションで確定する。並行した同じ要求は同じ結果を返し、同じIDの異なる入力は409で拒否する。継続期間を二重に加算しない。

APIは202で受付を返し、LLMは独立ワーカーで実行する。ブラウザーやHTTP接続の終了は、ジョブの中止・世界構築の完了にしない。状態に合わない操作と、内部障害を区別して返す。

## 公開情報とページ

管理APIは到達時刻・目標・状態、初期生成の報告、各処理の要約・継続内容・変更数を返す。グラフの全内容や内部メッセージを返さない。

村民APIは、その存在が受容したseeの側面と本人のinterpretだけを返す。管理診断、他者の知識、対象ノード全体、接続先IDは含めない。取得だけで観測を更新しない。Neo4jから取得する履歴をページに分け、1ページ50件と次のcursorを返す。総履歴を50件で切り捨てる制限にはしない。

## 進捗と再接続

進捗通知はPostgreSQLに保存し、安定したIDを付ける。構築状態の変更と通知を同じトランザクションで記録する。Neo4j確定後に停止した場合は既存のreceipt復旧経路を通り、復旧した進捗から通知する。保存済み状態を再取得しただけでは通知を増やさない。

SSEは公開データの再取得を促す通知だけを配信する。Last-Event-IDから未受信分を再送し、主体・世界・ロールが異なるcursorは拒否する。各取得と送信の前に現在の操作権を確認し、失効した接続を閉じる。失効前の判定や、ロール未分離の通知本文を使い回さない。0.5秒間隔の短い照会を使い、接続中ずっとDB接続やトランザクションを占有しない。

## 次の接続

人間の行動は、ユーザーの選択どおり、次に人間の判断が必要になる場面まで進める。NPCの反応は本人の意図形成を通し、継続状態を保持する。これは今回の構築受付APIだけで完成したとは扱わず、共通実行と公開画面へ続けて接続する。
