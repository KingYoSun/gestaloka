# ADR-004: 構築操作・公開知識・進捗配信の境界

状態: 採用。2026-10-19。

## 今回の完了範囲

導入時はIssue #31のうち、ローカルブラウザーの識別、世界ごとの操作権、構築受付とジョブ投入、再送、管理記録と村民の知識の取得、SSEの保存・再送を接続した。人間の自由記述行動と画面は[ADR-005](ADR-005-human-play.md)・[ADR-006](ADR-006-gameplay-ui.md)で接続済みである。認証・認可は[ADR-012](ADR-012-authenticated-world-access.md)、参加受付は[ADR-013](ADR-013-world-participation.md)が以下の導入時の方式を置き換える。再送・情報分離・ページ取得・SSEの境界は引き継ぐ。

## 導入時のローカル識別と現在の操作権

導入時は初回の同一オリジン操作でランダムなCookieを発行し、PostgreSQLへハッシュと主体IDを保存した。CookieはHttpOnly・SameSite=Strict、HTTPSではSecureとし、同じブラウザーで主体を復元する方式だった。現在の通常APIはOryの認証済みアプリIDと利用登録・BAN状態を確認する。匿名Cookieは本人が対象を確認して既存データを引き継ぐ所有証明に限って使う。

導入時は世界の作成者へ管理権を登録し、別の村民の生成後に同じ主体へ操作対象を割り当てた。現在はサービスの管理者が世界構築を扱い、参加者は本人に対応する操作対象だけを利用する。actorIdは複数の人物から選ぶ指定であり、自己申告のロールと同様、権限の根拠にはしない。未認証は401、未登録・BAN・管理権限不足は403、利用できない世界や操作対象は404で拒否する。変更操作は専用ヘッダーとOriginを確認し、異なるオリジンからのブラウザー操作を拒否する。認証済みの応答はキャッシュへ残さない。

匿名Cookieによる導入時の方式は、同じブラウザーでの再開だけを対象としていた。現在の別ブラウザーでのログインは[Oryの手順](../operations-auth.md)、本番のHTTPS配置は[公開配置と復旧](../deployment.md)を使う。CLIで作った世界にも現在のサービス管理権限を適用する。CLI実行だけでは利用者へプレイヤーの操作対象を割り当てない。

## 受付と再送

要求ID、主体、入力のハッシュ、受付結果をPostgreSQLへ保存する。構築記録、管理権、pg-bossへの投入、受付結果は同じ短いトランザクションで確定する。並行した同じ要求は同じ結果を返し、同じIDの異なる入力は409で拒否する。継続期間を二重に加算しない。

APIは202で受付を返し、LLMは独立ワーカーで実行する。ブラウザーやHTTP接続の終了は、ジョブの中止・世界構築の完了にしない。状態に合わない操作と、内部障害を区別して返す。

## 公開情報とページ

管理APIは到達時刻・目標・状態、初期生成の報告、各処理の要約・継続内容・変更数を返す。グラフの全内容や内部メッセージを返さない。

村民APIは、その存在が受容したseeの側面と本人のinterpretだけを返す。管理診断、他者の知識、対象ノード全体、接続先IDは含めない。取得だけで観測を更新しない。Neo4jから取得する履歴をページに分け、1ページ50件と次のcursorを返す。総履歴を50件で切り捨てる制限にはしない。

## 進捗と再接続

進捗通知はPostgreSQLに保存し、安定したIDを付ける。構築状態の変更と通知を同じトランザクションで記録する。Neo4j確定後に停止した場合は既存のreceipt復旧経路を通り、復旧した進捗から通知する。保存済み状態を再取得しただけでは通知を増やさない。

SSEは公開データの再取得を促す通知だけを配信する。Last-Event-IDから未受信分を再送し、主体・世界・ロールが異なるcursorは拒否する。各取得と送信の前に現在の操作権を確認し、失効した接続を閉じる。失効前の判定や、ロール未分離の通知本文を使い回さない。0.5秒間隔の短い照会を使い、接続中ずっとDB接続やトランザクションを占有しない。

## 後続の接続

人間の行動を次に本人の判断が必要になる場面まで進め、NPCの反応は本人の意図形成を通して継続状態を保持する処理は、ADR-005・ADR-006で共通実行と画面へ接続した。現在の通常プレイは[ADR-008](ADR-008-scene-synopsis-results.md)に従い、シーン中の背景情報・履歴と共有世界を分離し、終了時に表示済みの出来事・受容を確定する。
