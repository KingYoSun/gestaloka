# ADR-044: 下位モデルにMuse Emberを採用する

日付: 2026-11-17

状態: 採用。

## 決定と範囲

新しい応答のdefaultをOpenRouterの `meta/muse-ember` / lowへ変更する。resolutionのモデル・API形式・推論量・単価、判定方式、形式修復後の上位引継ぎ、予算と呼出し上限は変更しない。新しいプロンプトや検品ループも追加しない。

lowはdefault設定の値である。背景準備・参加選択がresolutionの推論量を使う既存ルールも保持するため、本番のそれらのEmber要求はmediumとなる。両群の上位をFlash / lowに揃えた比較時の背景lowとは区別する。行動・結果要約のlowと、背景のmediumを結合試験で確認する。

本番の変更前は設定版1で、下位がGemini 3.8 Flash / low、上位がGPT-6.1 Terra / medium / Responses、judgment=combined、応答呼出し上限128（版6）である。運用変更は共通のcredentials.putとmodels.putを使い、上位を元オブジェクトのまま保持してdefaultだけを完全な新設定へ置換する。Emberの通常入力/cache読取/出力単価は0.10 / 0.004 / 0.50 USD / 100万token。Flashのcache保存料や単価を引き継がない。

既存のModelSettingsによる応答ID単位の版固定を使う。保存済みの設定・要求・単価・Work.target・旧プロバイダー資格情報を削除・上書きせず、取得済みの旧応答はその設定版で続ける。切替後の新しい応答だけがEmberを使う。DBの自動一括移行や開始済みシーンのモデル差替えは行わない。

`.env.example`の下位をEmberに更新する。例の上位Sonnetの値は従来と同じになるよう明示する。本番の上位Terraは運用設定で保持し、既存デプロイの設定を起動時の環境変数で上書きしない。

## 根拠と限界

[実シーン比較](../evaluations/ember-flash-scenes-2026-11-17.md)は同じ保存状態から4試行、総計算額0.472354414 USD。人物・関係と次の選択に必要な情報が両場面で本人へ届き、Ember構成は2場面合計で約65%低費用だった。本人返答後の処理は修復・上位引継ぎにより遅くなった段階もある。上位引継ぎを除いたEmber単独構成の採用ではない。

比較の上位は両群Flash / lowであり、本番のTerra / mediumとの組合せを物語品質の比較で測定した記録ではない。今回の指示に従って本番上位を維持し、TerraのAPI形式・推論量と既存の引継ぎを結合試験で確認する。少数場面から全世界の品質や費用・待ち時間の分布を推定しない。

## 完了条件と判定方法

1. 実装・比較記録を最新mainに取り込んだPRを作り、必須CIを全て通過させてマージする。
2. OpenRouterのlow・JSON要求・使用量・独立単価を製品クライアントで検証し、保存済みの応答は旧Flash版、新応答の下位はEmber、上位と形式修復後の引継ぎはTerra / mediumのままとなることを実DBの結合試験で確認する。
3. マージ後のmainを本番のAPI・ワーカーへ反映し、ソースとビルドの一致、health、公開画面を確認する。
4. 本番の新設定版でdefaultだけがEmberへ変わり、旧設定版・既存の応答と版の対応・上位設定・呼出し上限が保たれたことを読取り照合する。新規の小さい接続確認は専用費用枠0.20 USD以内で行い、通常プレイの世界や人物を操作しない。

追加のシーン比較や、他の世界・人物への改修はこの採用作業に含めない。
