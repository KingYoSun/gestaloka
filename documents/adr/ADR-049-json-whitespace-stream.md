# ADR-049: JSON文字列外の空白連続でストリームを中断する

状態: 採用。2026年11月17日のユーザー指示に基づく。追加の有料生成は行わず、CI通過後に本番へ反映する。

## 原因と対象

Emberの保存済み上限終了43応答のうち41件で、JSON文字列の外の空白連続が続いていた。修復用の空白縮小は次の入力を小さくするが、元の応答の受信完了を待つ。現在の提供元には、文字列外の空白連続を指定できる公開パラメーターを確認できていない。

下位担当の構造化応答をOpenRouterのChat Completionsで受ける経路を対象とする。提供元・モデル・推論量・最大出力・修復回数は維持する。通常プレイへ検品用の呼出しを追加しない。

## 決定

構造化応答をストリーミングで要求する。`delta.content`だけをJSONの本文として処理し、推論フィールドを混ぜない。引用符とエスケープの状態を断片間で保持し、文字列外の空白・タブ・CR・LFが64文字を超えたら接続を中断する。正常255応答に最大45文字の空白連続があったため、32文字ではなく64文字を採用する。文字列内の空白・改行・引用符や選択肢は制限しない。

中断時までに受信した本文を保存し、未完成の応答を表示せず既存の形式修復へ渡す。既に受信バッファにある完全なイベントは処理し、最終使用量があれば精算する。中断後に次のネットワーク読取は行わない。通常完了時も、最終使用量と終了情報を検査する。

最終使用量が未受信・不正・不整合の場合は、使用量不明として予約額を保持する。受信文字数・断片数からトークン数や0円を推定しない。保存した中断理由と本文から再開でき、同じ呼出しIDを再送しない。修復は既存の別IDを使う。

接続の中断が提供元の生成・課金を止める保証はしない。OpenRouterの公開仕様ではGoogleは中断による生成・課金停止に非対応で、Metaの保証も確認できていない。ローカルの待機を打ち切って修復へ進むことと、提供元の請求削減を区別する。未確定予約は費用集計でも別枠のまま残す。

SSEのフレーム処理とJSONの文字列判定は既存処理と共有する。保存済みの非ストリーミング要求・応答は書き換えず、同じIDの再利用では保存した要求を維持する。外部API・CLI・保存済みの物語の形は変えない。

## 完了条件

1. 非追跡領域で保存済み正常JSON255応答を受信後も同じ文字列・値で返し、保存済み上限終了43応答の41件で空白連続を中断する。残る2件は別の上限終了として扱う。本番の本文・識別子はGitへ入れず、CIには新しく作成した架空の例だけを使う。
2. 引用符・逆斜線・Unicode・文字列内の長い空白と改行、SSEの断片・コメント・最終使用量の両形式を試験する。内容にある未選択の候補を変えない。
3. 最終使用量を受信した中断は実測値で一度だけ精算し、未受信・不正・不整合なら予約を保持して形式修復へ進む。推論は本文や修復入力へ入れない。再起動後も元の呼出しを再送しない。
4. 関連する単体・結合試験と必須CIを通し、マージしたmainを本番へ反映して実行物とhealthを照合する。有料の生成比較による削減率や、新しく生成した物語の品質を確認したとは扱わない。
