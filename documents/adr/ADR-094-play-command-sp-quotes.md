# ADR-094 プレイコマンドのSP見積もり

2026年11月25日に #465 の方針を採用した。[ADR-091](ADR-091-typed-world-application.md) の料金を専用コマンドの見積もりにも使う。

## 料金と消費の条件

| 操作                                                          | 予定SPの上限                                                                       | 消費の条件                                        |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------- |
| `apply` の正式改名                                            | 1                                                                                  | 採否を保存する                                    |
| `apply` の生成、状態変更、対抗、個数増加                      | 1。複数の生成案は案ごとに1                                                         | 新しい出目を保存する                              |
| `explore`、登場申請付きの `say`                               | 1                                                                                  | 新しい出目を保存する                              |
| `npc-action` の作用、対抗を指定した `vehicle-request-control` | 1                                                                                  | 新しい対抗の出目を保存する                        |
| `blueprint-start`、GM審査が必要な `companion-request`         | 1                                                                                  | 採否を保存する。同行を相手に受領してもらう場合は0 |
| `draw`                                                        | 公開表に生成物・技能が含まれる場合と、旧説明式の抽選は1。在庫・外れだけの公開表は0 | 抽選結果を保存する                                |
| 上記以外の操作                                                | 0                                                                                  | SP消費なし                                        |

## 見積もりと受付

Web、CLI、botは同じ契約から、予定SPの上限と消費の条件を取得する。固定の上限はコマンドから計算できる。公開表の料金は対象と公開版を確認して求める。見積もりの取得では抽選、審査、予約、世界への変更は発生しない。

受付は提出された上限を照合する。料金が上がっていれば再見積もりを求める。抽選の公開版が変わっていれば、その版の料金と代価を改めて確認する。出目を再利用できた場合は既存の精算で消費を免除する。保存済みの結果の再送では、確定した結果と消費SPを返す。

専用コマンドの上限確認は既存APIに任意項目として追加する。旧クライアントは従来の手順で利用でき、`apply` には既存の `expectedSp` を使う。

場所の状態が移動に影響する場合は、人物、始点と終点、参照した状態とその版が同じときに移動可否の判断を再利用する。状態の追加、終了、期限到達、本文改訂で条件が変われば、それに基づいて可否を扱う。確定時は場所と所在の依存版も照合する。
