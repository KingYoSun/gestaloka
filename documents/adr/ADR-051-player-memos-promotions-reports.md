# ADR-051: メモノード、NPC昇格、運営への報告

状態: 実装中。2026年11月18日にユーザーが追加した#227のマージ条件を記録する。3要件の実装と検証が揃うまでマージしない。

## メモノード

メモは本文を自由記述するscriptノードの種別とし、用途を同意や約束に限定しない。existence・script・eventと既存の関係種別を維持し、scriptに任意の`type: "memo"`を追加する。関係する人物からメモへの`has`で関連付ける。

通常プレイの`memo`で作成し、本人以外の人物を関連付けるときは既存の受領手続きを使う。全員が受け入れるまでメモを確定しない。拒否・退出・期限切れ・セッション外申請は既存の手番APIの扱いを引き継ぐ。作成と更新の影響範囲は関係から求め、再送で二重適用しない。本文の内容をGMに採点させない。

## インスタントNPCの昇格

プレイヤーは、本人が登場させたか受容したインスタントNPCを、元の発言要求とその中の番号で指定して昇格を申請する。継続する存在の説明と、必要なら本人への所有関係を添える。申請中はNPCを表すノードを作らない。

管理者はMCPまたはWebの運用操作で申請の出現情報と説明を読み、承認・却下する。承認時に同一性、説明、所在地、指定された所有関係を共有グラフへ原子的に記録する。同じ出現を重ねて別のNPCへ昇格させない。却下ではグラフを変えない。

昇格したNPCは操作担当が未割当の状態で登録する。bot担当・サーバー担当は既存の個体別指定を使い、昇格だけでは自動で動かさない。

## 報告・感想

プレイヤーが運営へ自由記述を送る専用APIとCLIを用意する。世界の正本やセッションのチャットは変更せず、運営のMCP・Webから確認する。報告内容はプレイヤーの申告として保存し、世界の事実やIssueへ自動変換しない。

ユーザーが選んだ初期値は、1ユーザー×世界ごとに日本時間の1日最大10件、本人の通常手番3回終了で1件分、1件1,200文字である。通常手番の完了は本人が操作したユーザーへ一度だけ記録し、当日の完了数から送信枠を求める。未プレイ時は0件。状態照会・再送・受領判断だけでは手番数を増やさない。

管理者は日次上限、必要手番数、文字数上限を任意のタイミングで変更できる。新しい送信では現在の設定を使い、受け付け済みの報告は変更しない。上限を既送信数より下げたときは、新たな送信可能数を0とする。エラーでは枠を消費せず、同じ要求の再送も重複送信へ数えない。

## 受入条件と判定

| 対象           | 期待結果                                                               | 判定方法                                                                    |
| -------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| メモ           | 自由な本文を関係する人物へ関連付け、本人以外の受領後に一度だけ確定する | 共有・拒否・期限・遠隔・再送・更新を結合試験で照合                          |
| 昇格申請       | 受容した出現を指定でき、申請中と却下では永続NPCを作らない              | 本人・同席者・未観測者の申請とグラフ差分を照合                              |
| 管理者の許可   | 管理者だけが承認でき、同じ出現から一度だけNPCを作る                    | MCP・Webの認可、承認再送、同時申請を検証                                    |
| 昇格後の担当   | 未割当で保持し、個体別の指定後に担当だけが操作する                     | 登録と担当指定を既存NPC処理に接続して確認                                   |
| 報告の枠       | 当日の通常手番と日次上限から送信可能数を求める                         | 日本時間の日境界、3手番の境界、10件の上限、別ユーザー・世界、並列送信を検証 |
| 設定変更       | 3つの上限を運用中に変更し、新しい送信へ反映する                        | 文字数・必要手番数・日次上限の変更と既存記録を照合                          |
| 送信と運営閲覧 | 1件1回だけ保存し、プレイヤー本人の認可と運営の閲覧範囲を守る           | API・CLI・MCP・Web、再送・エラー・文字数境界を検証                          |
| 通常プレイ     | 追加機能の受付と確定に生成LLMを使わない                                | 呼出しを監視する結合試験と既存の手番試験を実行                              |

実装の調査は、既存の受領・原子的確定、個体別NPC操作、認可と運用操作、手番終了、CLIの各入口を特定した時点で終える。調査から新たな利用場面や上限を追加しない。
