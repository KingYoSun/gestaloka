# ADR-050: botが個別に世界を読み、手番の結果を共有する

状態: 実装・検証中。#225の合意事項と、2026年11月17日のユーザー判断を記録する。対抗行動の一次判定範囲と観客評価は確認待ち。本番への適用は未実施。

## 問題

従来の通常プレイでは、サーバーが場面の背景、参加者の意図、結果、終了時の提示を生成していた。参加者が自分のLLMを使っても、会話の往復ごとに運営側の生成費用がかかる。また、各人物の解釈をサーバーがまとめるため、参加botが別々に素材を選んで解釈する余地が小さい。

## 合意済みの範囲

世界の正本と原子的な確定はADR-001を維持する。通常の検索、接触、合流、発言、受領判断、分離、本人の終了では、サーバーの生成LLMを呼ばない。ワールド生成とキャラクター生成、明示指定されたサーバーNPC、新規作成の可否が規則で決まらない申請、対抗行動のダイス設定を分けて集計する。上位モデルと下位モデルの設定は維持する。

各botは用途別の検索APIから本人に提供される素材を取得する。共通背景、検索結果、私的な解釈をセッションへ同報しない。1人以上で手番を回す単位をセッションとし、手番の終了時に入力と結果をチャットへ提示する。本人ごとのシーンID、履歴、リザルトは内部の合流・分離をまたいで継続する。

通常APIコール枠の初期値は8回、受領判断の無応答期限の初期値は600秒とする。いずれも管理者が変更できる。手番の本人は別枠で0回または1回コメントでき、コメントは当該セッションだけに保存する。

成功した素材検索・接触申請・世界への更新申請を通常枠へ数える。エラーになった申請、状態確認、チャット取得、同一要求の再送、ターンコメントは数えない。

接触は確定済みの所在地等から決定論的に判定する。不一致では、本人が知り得る理由を返す。移動後に再申請でき、GMの判断待ちにはしない。

更新は認証された申請者の操作として受け付ける。型、権限、現状態、依存版を検証し、受理した差分だけを原子的に確定する。同じ要求の再送では結果を復元する。物品・所有・保持・保管・技能・所在地には既存の内部関数を使う。借り手のholdがある物の破棄に、貸し手の承認を要求しない。

同席者の受領判断は通常順へ割り込み、終了後に元の手番へ戻る。退出・無応答なら申請をfailedとし、未成立の変更を適用しない。セッション外への受領申請は即時エラーとする。

受領を経ない対抗行動は別の処理とする。確定グラフだけで成功可能性が0%・100%と決まる場合はGMもダイスも使わない。不確実な場合は用途別の材料をGMへ渡し、ダイス設定だけを得る。抽選と確定、再送時の出目の復元はサーバーが担う。

ユニークNPCは個体ごとに、GMが用意するbotかサーバーNPCモードを明示指定する。一般参加botの切断・無応答を理由に代演しない。インスタントNPCは共有グラフへ永続化しない。

通常プレイの書込は新しい手番API・CLIへ統一する。旧書込には移行先を示すエラーを返す。過去のシーンと履歴の読取は残す。この互換性変更はユーザー確認済み。

移行する旧NPC18人のうち、提案した6人を在村とし、残る12人を村外へ転居させる。利用者の人物とその物品は転居対象に含めない。氏名・識別子・過去の参照は非追跡の移行計画で照合する。この配置はユーザー確認済み。

## 実装前の調査

次の調査は、それぞれ記載した結果が得られた時点で終える。調査から新しい受入条件を追加しない。

| 対象         | 調査の終了条件                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------- |
| 停止した本番 | 停止状態のDB・設定・実行情報を退避し、アーカイブとハッシュを照合する                              |
| 既存実装     | グラフ確定、物品・所在地、本人の連続履歴、認証、CLI、通常進行の入口を特定する                     |
| 移行対象     | 複製したDBで旧NPC・利用者の人物を区別し、在村候補と転居候補、過去の参照、未処理ジョブを一覧化する |

## 完了条件

#225のチェック項目を次の対象と方法で検証する。全項目の完了までは移行完了としない。

| 対象                 | 期待結果                                                                                                                | 判定方法                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 停止時点の記録       | 移行前の状態を保持し、複製で移行・起動できる                                                                            | 退避のハッシュ、復元、人物・物品・履歴の件数と参照を照合              |
| 旧NPCの転居          | 交流の多かった人物を在村とし、他の旧NPCの転居と現所在地を記録。転居者は村内接触候補に出ず、過去から同じ人物を参照できる | 旧NPCだけを対象に、移行前後の所在地・出来事・関係を照合               |
| 旧進行の再開         | 旧NPCフラグや未処理ジョブから個別指定のない人物を自動生成しない。過去の記録は読める                                     | 旧状態を含む復元データと結合試験で再開を確認                          |
| NPCの区別            | bot担当とサーバー担当を個体ごとに指定でき、インスタントNPCの同一性を永続化しない                                        | 両担当の動作と共有グラフの差分を照合                                  |
| 生成                 | 世界と人物の生成が従来のモデル設定を使って動く                                                                          | 実モデルで生成し、設定版と保存結果を確認                              |
| 個別検索とセッション | 複数の実botが個別に検索し、単独開始・接触・合流・手番・分離・本人の終了まで遊べる                                       | API/CLIの試遊記録と本人ごとの連続履歴を照合                           |
| コール枠とコメント   | 8回で次の手番へ進む。コメントは別枠で本人の手番に1回だけ、当該セッションだけに保存                                      | 枠の境界、0・1・2件目、他人・別セッション、グラフ差分を結合試験で確認 |
| 接触と受領           | 不一致の理由から移動・再申請できる。受領・拒否後に元手番へ戻り、退出・600秒の無応答はfailed。遠隔申請は即時拒否         | 時計を制御した結合試験と試遊で正本・チャットを照合                    |
| ノード・エッジ作成   | 規則で許可・拒否できる場合はGMを呼ばず、残る判断だけ用途別の材料を渡す                                                  | 許可・拒否・判断必要の各経路の呼出しと確定を照合                      |
| 借り物と対抗行動     | 借り手が承認なしに破棄できる。0%・100%ではGMも抽選もなく、不確実な場合は設定・抽選・確定が一度だけ                      | 保持・所有が異なる例と再送を結合試験で確認                            |
| 費用                 | 参加bot同士の通常プレイで運営側の生成呼出しが0回                                                                        | 実botの試遊前後で用途別の呼出し・エラー・再申請を計測                 |
| 観客の体験           | 入力・結果・任意コメントから、人物固有の解釈と他者の一手による発展を読み取れる                                          | 試遊者の反応と提示全体を評価。特定の台詞・行動・結末を期待値にしない  |
