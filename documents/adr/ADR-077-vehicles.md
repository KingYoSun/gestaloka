# ADR-077 乗り物の所在と操縦

実装範囲と判定は [#351](https://github.com/KingYoSun/gestaloka/issues/351) に定める。乗り物の現在地が変わると、すでに乗っている人と積荷も移る。乗り物になった既存NPCの同一性と会話履歴は引き継ぐ。

## 共有グラフ

- 乗り物は既存の `existence`。その存在から説明の `script` へ、`status/content` の `text: "vehicle"` を付ける。どの存在にこの性質があるかは、世界の記録で決まる。
- 経路が能力を必要とする場合、既存の経路の `script` から能力を表す存在へ、`status/about` の `text: "route-requires"` を付ける。能力を持つ人物や乗り物には `status/content` の `text: "capability"` で説明の `script` を付け、その `status/about` から同じ能力を参照する。徒歩・自動運転・操縦・同行による移動で、この参照を同じ方法で照合する。乗車中の経路は乗り物の現在地から引く。
- 専用の操縦権は、乗り物から説明への `status/content`（`text: "operator"`）と、その説明から操縦者への `status/about` で表す。乗り物ごとに有効な操縦権は一つまで。交代時は旧関係の終了と新関係の開始を同じ確定に含める。
- 乗客の直接の所在は、乗っている乗り物のID。積荷は乗り物から品への役割なしの `has`。乗り物を携行・保管している間は保持先をたどって地点を求める。現地に出したときは、その地点を乗り物自身に記録する。

## 確定

専用の乗降・運行コマンドは `locate` の計画に通す。乗り物自身の通常手番では自動運転を扱い、同乗中の操縦者と成立済みのコンパニオンにはそれぞれの権限を適用する。同行者の追従は直接の所在を使い、乗る対象と降りる対象の乗り物を追従から外す。乗客のいるNPC乗り物自身とその乗客は同じ車内として接触・セッション分割を行う。

操縦権は現地で申請する。所持への対抗では箱を持つ人物を調べ、登録済み保管先では既存の取り出し権限を照合する。第三者への対抗とNPC自身への対抗は、申請者が同じ `oppose: true` で明示する。同じ人物への判定を一回にまとめ、申請者は相手から外す。NPC本人が通常の申請を承認した場合、申請者はその申請IDを指定し、明示フラグ付きで第三者への対抗を続けられる。

対抗の設定と出目は要求IDと相手から導いたIDで保存する。全員への対抗が成立した時点で、必要な所持と操縦権の変更、消費を同じ差分として確定する。同時申請では操縦権・所持・所在・保管先の依存版を確認する。出発が先に確定した場合、元の地点からの乗車では `VEHICLE_NOT_HERE` が返る。

プレイヤーは `search --kind surroundings` で乗り物と乗客の一覧を、`search --kind self` で乗車中の所在を確認できる。CLI の操作は `help vehicle` を参照する。

## 隔離試遊

2026年11月22日。専用の PostgreSQL と Neo4j に架空の世界を用意し、配布用 CLI 1.8.0 を実 API へ接続した。別の人物が操縦する台車への通常申請には `VEHICLE_OPPOSITION_REQUIRED` が返り、対抗を明示した申請で操縦権が交代した。この場面は再現可能なダイス設定で確認した。

乗合車のNPCには、車内から「作業場までお願いします。着いたら荷下ろしを手伝います」と声をかけた。Claude Sonnet 5.5 はNPCの手番で運行、発言、手番の終了を順に選んだ。乗客は作業場に到着して降りられ、広場にいた人物は広場に残った。乗客はNPCの手番を挟んで移動し、到着先で荷下ろしを選べる状態になった。
