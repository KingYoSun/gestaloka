# ADR-017 保存済みの提示情報を用いた物語検品

状態: 採用

## 対象と境界

Issue #102〜#106の検品を、提示記録、決定論的計測、意味評価に分ける。原則は「世界の因果とプレイヤーの選択を両立する」。生成の最適化や品質点による世界の自動修正は行わない。

本人向けの投影と同じあらすじ、receipt、リザルトを保存時に記録する。提供時刻は、その出力をサーバーから取得できるようになった時刻であり、閲読や理解を意味しない。世界内時点とは別に扱う。背景、NPCだけの受容、内部の照会、未提示の世界確定を新情報量に含めない。評価記録は世界グラフへ保存しない。

新規シーンは`inspection-record-v1`の提示記録を持つ。旧記録の本文は本人向け投影から取得できるが、入力との対応・提供時刻・グラフ対応を推測せず欠測にする。既存生成の同じ応答へ対応メタデータを加える。採点専用の生成呼出しは追加しない。

## 計数規則 presentation-v1

プレイヤー視点は世界、利用者、操作対象の組で識別する。世界のIDは管理APIのconstruction IDを用いる。シーンは`created_at, id`、シーン内の提示は保存済みordinalで順序を固定する。指定終端以前の連続nシーンを選び、実件数、各シーンの状態、記録版を返す。途中・保留でも取得時点までの提示済み情報を扱う。

窓より前の同じ視点の提示を既提示集合へ投入する。その後、提示順に、各対応項目を次の優先順で一つの区分へ分類する。

| 区分   | 有限の判定規則                                                   |
| ------ | ---------------------------------------------------------------- |
| repeat | 同じkind、ID、aspect、state、version、atの組が既提示。加点しない |
| node   | repeatでなく、そのノードIDを初めて提示                           |
| edge   | repeatでなく、そのエッジIDを初めて提示                           |
| aspect | 上記以外で、同じ要素のaspectを初めて提示                         |
| update | 同じ要素・aspectについて、未提示のstate、version、atの組を提示   |

各項目を処理するたびに要素・側面・状態の集合へ加える。原点へ戻った状態も、同じ組を既に提示していればrepeatとなる。同一提示内の重複、リザルトの再要約、再取得も同じ規則で除外する。初ノードと、そのノードの最初の側面を二重に数えない。originのreference/generatedは内訳であり、加点区分を増やさない。

ローカルeventとseeのIDは、世界確定時のsceneAnchorsと共通にする。メタデータの$event、$receipt、背景の配列位置は、保存時にそのIDへ解決する。新たな観測を計測のために作らない。意味が同じでも別IDなら構造上は別要素となる。本文の引用と対応情報の意味的一致、別IDの同義内容、入力の復唱は意味評価でも確認する。

`M = Σ(w_k × c_k)`。初期のunit-v1はnode/edge/aspect/updateをすべて1とする未校正の基準値。固定重みは値と根拠を含めてmanifestへ保存し、別の設定版として指定できる。LLMが実行中に重みを変更する経路は設けない。生の件数を常に併記する。

対応配列が空なら対応する新情報なし、配列なしなら対応不明。計測値が確定できなければvalueはnull、確認できた部分はobservedValue、対応済み比率と不足IDを別に返す。窓前の欠測があれば全体値も確定しない。件数不足は要求件数と実件数に、途中・保留は各シーン状態に残す。

入力への応答、あらすじ、リザルトを別に集計する。入力当たりの値は入力応答だけを分子とする。指定閾値以下の入力が続く区間を入力ID順で返し、不明な入力で連続を区切る。

費用は既存llm_callの計算額を使用する。呼出しのresponse IDで準備、入力、反映を対応させ、準備や反映を入力へ按分しない。応答待ちは入力受付から操作を返せる保存までの時間、modelCallMsは各モデルcall時間の合計。世界内経過時間やブラウザーの通信時間と混同しない。費用・時間が不明なら効率値もnullにする。部分計測の効率値は確認済み部分の値を分子にする。

## 不変の資料と共通実行

選択したシーン、窓前の提示、既存費用を一つのDBスナップショットで固定する。指標、重み、対象順序、記録内容のhashからmanifest IDを作り、同じ保存内容の再集計を再利用する。後日のグラフ状態を混ぜない。根拠は安定したIDを持つページとして保存する。以後のページ取得はその資料だけを読む。DBとバックアップの保持中は再現可能で、削除・復元により存在しないIDは404とする。

管理APIとMCPは共通Operationを通し、既存の管理者、scope、対象世界の制約と監査を適用する。プレイヤーAPIへ内部資料を追加しない。開発コマンドもAPIから全ページを取得し、同じ計測値を報告する。

意味評価は`.agents/skills/narrative-inspection`の同じ本文・ルーブリックを使用する。評価は別実行として保存し、モデル設定版、本文hash、実行ID、費用上限、費用・時間を記録する。評価中に世界更新やプレイヤーの選択を行うツールを公開しない。引用と提示IDの対応を検証する。LLMの推定を満足度の実測とは扱わない。

## 定期処理と期間集計

既存pg-bossのワーカーで、設定済み世界の指定期間にある変更シーンだけをページ取得する。プレイ応答は採点を待たない。意味評価は設定した頻度ごとの固定バッチにし、候補全体と選定IDを保存する。バッチIDとmanifest IDのhash順で所定件数を選び、低得点だけを抽出しない。予算はバッチ全体で共有し、送信前予約を含めて制限する。未確定callは自動再送せず、予算終了や不足を部分評価として保存する。

期間の分布・平均は同じ指標、重み、n、生成モデル・設定版の窓単位で求める。異なる条件は別系列。シーン、入力、費用の総計は元IDで重複を除く。意味評価はモデル・ルーブリック・サンプル数を伴う別の記録として表示し、原則違反を移動量で相殺しない。

## 負担と検証

追加の採点callは0でも、対応情報を出力するトークンと保存量は増える。有限fixtureと実モデルの試行で、出力・保存の量、計算額、待ち時間、計測処理の時間を記録する。同じ保存記録の取得・再計測では、追加call、生成費用、プレイの待ち時間を増やさない。メタデータなしで再生成した場合の費用差を、保存記録から推測して実測と呼ばない。

判定は計数fixture、シーン統合試験、API/MCP契約試験、ワーカー試験、管理画面試験で固定する。意味評価の8種類のfixtureは実モデルでも確認し、CIでは構造と根拠の検証を有料APIから独立して行う。物語の結末や毎回のLLM点数は合格条件にしない。
