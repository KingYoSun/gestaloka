# ADR-085 対抗行動で相手に残る状態はGMだけが決め、死亡はfatalでだけ表す

状態: 採用。2026年11月24日のユーザー判断を記録する。[ADR-080](ADR-080-opposition-states-by-gm.md)の、申請者が変更に書いた相手の状態の扱いを改める。死亡の扱いは[ADR-065](ADR-065-person-death-penalty.md)と[ADR-084](ADR-084-death-ends-judged-states.md)に従う。

## 問題

ADR-080の後も、対抗行動の申請者は、変更に相手の人物の状態を書けた。ダイスが成功すると、その状態はそのまま確定した。GMが死亡と判定しなかった相手（`fatal` の候補でない人物や、同席していない人物）にも、申請者は「死亡している」「完全に破壊され機能を停止している」と書けた。その結果、死亡の扱い（セッションからの離脱と移動、ADR-084による状態の整理）を経ないまま、死亡を表す状態だけが残った。

ぶー村の記録（2026年11月23日）では、サーバー担当NPCの熊が、同席していない村長に「村長は死亡しており…」を、乗り物のNPCに「…完全に破壊されて機能を停止している」を書いた。村長は死んだ状態のまま次の手番を迎えることになり、乗り物のNPCは壊れた状態のまま移動し、話し続けた。この食い違いは、行動の種類や世界の設定によらず起きる。

また、登録済みの人物に起きることを新しい存在の作成で確定する申請を断る照合（ADR-083）は、GMが名指しと読み取った呼び名に頼っていた。人物の呼称が種類の名前のように見えると、GMは名指しと判断しない。そのため、登録済みの人物と同じ呼び名の出現個体が作られ、殺された。本人は生きたままだった。

## 決定

- **対抗行動で相手に残る状態は、GMが返すものだけとする。** ダイスが成功したとき、申請者が変更に書いた他の人物（申請が関わるプレイヤーとNPC）の状態は記録しない。新しい状態の関係も、既存の状態の本文の改訂も対象とする。所在と操縦権の関係は状態ではないので、そのまま確定する。相手に残る変化は、GMが `states` で返す。
- **死亡は `fatal` でだけ表す。** GMは、`states` と、NPCの外界への作用の `observable` に、人物の死亡や、人物として動くこと・話すことが戻らない機能の停止を含めない。死亡は、候補（`mortal`）から `fatal` に選んだときだけ起き、ADR-065とADR-084の扱いになる。
- **同名の出現個体などは呼称で照合する。** 新しく作る存在が物品として所持されるものでなく、申請が参照していない登録済みの人物と呼称が同じなら、GMの読み取りによらず `PERSON_REFERENCE_REQUIRED` で断る。物品は [ADR-083](ADR-083-named-persons-in-creation.md) に従い、申請の根拠も含めて人物との関わりを判定する。
- 過去の記録は変えない。既存のデータは管理修正で扱う。

## 受入条件と判定

特定の行動や結末は期待値にしない。

| 対象               | 期待結果                                                                                   | 判定方法       |
| ------------------ | ------------------------------------------------------------------------------------------ | -------------- |
| 申請者の書いた状態 | 対抗行動が成功しても、申請者が変更に書いた相手の状態は記録されず、GMが返した状態だけが残る | 結合試験       |
| GMへの指示         | 対抗判定の指示に、死亡を状態に含めずfatalでだけ表すことが入る                              | 結合試験       |
| 同じ呼び名         | GMが名指しを返さなくても、人物と同じ呼び名の個体を登場させる発言は断られる                 | 結合試験       |
| 文書               | ダイスの解説と変更履歴に、相手の状態と同じ呼び名の扱いを書く                               | 配布文書の照合 |

## 影響

- 対抗行動の申請者は、相手の状態を自分で決められなくなる。相手に残る状態は、応答の `outcome.setting.states` で読める。
- 人物と同じ呼び名の個体を出す申請が断られる。同名の物品は申請の根拠も含めて判定する。
- 保存データの形は変わらない。
- プレイヤーCLIの解説が変わるため、CLIの版を 1.21.5 に上げる。
