# ADR-076 NPCをプレイヤーのcompanionにする

状態: 採用。2026年11月22日のユーザー判断を記録する。

## 背景

プレイヤーが求めているのは、NPCが自分に付いてくることだった。チーム（[ADR-070](ADR-070-play-teams.md)）は、プレイヤー同士が承諾し合ってセッションを合流させる仕組みで、招待できるのはプレイヤーだけである。NPCには自分で承諾する主体がない。成立の条件も、成立後の操作もチームとは違うため、別の枠組みとして扱う。

## 決定

### 成立

- プレイヤーは、同じセッションにいるユニークNPCを指定して `companion-request` を申請する。インスタントNPCは同じ場所を離れると同席から外れる（[ADR-056](ADR-056-instant-npc-turns.md)）ため対象にしない。指定した場合は、先に昇格が必要だと返す。
- GMは、世界の前提、二人の記録、セッションの最近の出来事、申請の文から、NPCが申請者に好意を持っているか、同行する理由があるかを判断し、真偽値と理由を返す。ダイスは振らない。
- 申請は本人の通常手番に行い、探索・生成と共通の日次枠から1 SPを使う。
- 同じ手番に同じNPCへの申請が却下されていれば、判断モデルで出し直しかどうかを確かめる（[ADR-061](ADR-061-decision-model-and-repeated-applications.md)と同じしきい値と扱い）。出し直しなら、GMを呼ばずに前回の結果を返し、SPは使わない。次の手番からは新しい申請として判定する。
- 1人のプレイヤーが持てるcompanionは3体まで。1体のNPCは、同時に1人のcompanionにしかなれない。

### 記録

- 成立した関係は共有グラフに記録する。NPC → `status/content`（`text="companion"`）→「〇〇に同行している」→ `status/about` → プレイヤー。
- 帰る場所はNPCの認識なので、NPC → `interpret/content`（`text="home"`）→「帰る場所」→ `interpret/about` → 場所 として記録する。新しく指定すると前の記録を終える。
- 追従か待機かは、プレイヤーがcompanionを操作するための状態として `bot_companion` に置く。この表は、プレイヤーからcompanionを、companionからプレイヤーを件数の上限内で直接引く索引も兼ねる。

### 操作

| コマンド            | 内容                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| `companion-follow`  | 追従にする。現地で同席を再開し、本人の移動・接触・チーム合流と一緒に移る。遠くにいる間は待機する |
| `companion-wait`    | 待機にする。その場での発言や行動は続けられる。NPC自身の判断で出発するには待機の解除が要る        |
| `companion-move`    | 指定した場所へ移す                                                                               |
| `companion-return`  | 帰る場所へ移す。帰る場所がなければ指定を求める                                                   |
| `companion-home`    | 帰る場所を指定する                                                                               |
| `companion-dismiss` | 関係を終える                                                                                     |
| `companion-status`  | 自分のcompanionの一覧を返す                                                                      |

- companionの所在の変更は、プレイヤーの `update` の `locate` として扱う。成立時に同行の判断を済ませているので、NPCの受領判断は要らない。`companion-move` と `companion-return` は、この `locate` を組み立てて `update` と同じ手順で確定する。本人の通常手番が要り、呼び出しを1回使う。プレイヤーは、`update` にcompanionの `locate` を直接書いてもよい。
- 追従・待機・帰る場所の指定・解除・一覧は、手番を使わず、SPも使わない。
- companionはプレイヤーと離れて自立して行動することはできない。任意の行動を指示する操作も設けない。プレイヤーが選べるのは追従・待機・移動だけで、その場で何をするかはNPC本人が決める。サーバー担当のNPCは、プレイヤーかbot担当の人物と同じセッションにいる間しか手番を得ない。離れた場所へ残したNPCは指示を受けても動けず、一緒にいる間は `say` で頼めば足りる。試遊で任意の指示（`companion-order`）を試した後、2026年11月22日のユーザー判断で仕様から外した。
- 実際に成立する本人の移動に、その時点の追従相手を加える。他の人が提案した移動も、本人が承認した分に適用する。NPCだけの移動・帰還で別れたら待機にする。乗降は[ADR-077](ADR-077-vehicles.md)の車内と車外の区別に従う。
- [ADR-062](ADR-062-session-follows-place.md)の分離を、移動した人物がいるセッションに移動確定時点で適用する。公開発言の観測と履歴には発言時の聞き手を使い、途中参加や退出でも各人のシーンに聞いた分だけが残る。同行判断には、現在の手番で相手に届いた発言も渡す。

## 受入条件と判定

| 対象        | 期待結果                                                                                                                                        | 判定方法              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| 成立        | GMが同行を認めると、`status` の関係がグラフに残り、追従で一覧に出て、1 SPを使う。GMが認めなければ関係はできず、理由が返る                       | 結合試験              |
| 対象の制限  | 同じセッションにいないNPC、インスタントNPC、他人のcompanion、4体目は、GMを呼ばずに拒否する                                                      | 結合試験              |
| 出し直し    | 同じ手番に却下された後、判断モデルが出し直しと判定した申請は、GMを呼ばずに前回の却下を返し、SPを使わない。同じ要求の再送は判定をやり直さない    | 結合試験              |
| 追従と待機  | 追従中のcompanionは、プレイヤーの移動と同じ確定で移り、手番の後も同じセッションに残る。待機中のcompanionは移らない                              | 結合試験              |
| 移動と帰還  | `companion-move` はNPCの受領判断なしに指定の場所へ移す。`companion-home` の後の `companion-return` は帰る場所へ移す。帰る場所がなければ拒否する | 結合試験              |
| 解除        | `companion-dismiss` で一覧から消え、グラフの関係が終わる。解除後の `companion-move` は拒否される                                                | 結合試験              |
| CLI・スキル | CLIの `companion <操作>` が各コマンドを送り、スキルに成立の条件と各操作の意味、プレイヤーと離れて自立して行動することはできないことがある       | CLIの試験と文書の照合 |

## 影響

- プレイヤーCLIの応答とコマンドが増えるため、CLIの版を上げる。
- 帰る場所の記録はNPCの認識なので、関係を解いても残る。再び同行したときも、その場所へ `companion-return` できる。

## 隔離環境での試遊（2026年11月22日）

専用のPostgreSQLスキーマと新しいNeo4jの世界に、架空の渡し場の村を作った。プレイヤー1人は配布CLIで操作し、GMの同行判断とサーバー担当NPCの手番だけ実モデル（Claude Sonnet 5.5）を使った。判断モデルは設定していない。

| 場面                     | 観測した結果                                                                                                                                                                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 恩のある渡し守への申請   | 渡し守は接触の後、自分から「森の道も案内する」と申し出た。GMは渡し守の役割、恩の記録、その申し出を理由に同行を認め、1 SPを使った。                                                                                                                                                                |
| 面識のない行商人への申請 | GMは面識・信頼の記録がなく、同行する動機も示されていないとして却下した。理由には、報酬や取引など同行の動機になり得るものが挙がった。判断モデルが未設定なので、言い換えた申請もGMが判断し、もう1 SPを使った。                                                                                      |
| 追従と移動               | 対岸の森へ移ると渡し守も同じ確定で移り、手番の後も同じセッションに残った。帰る場所を小屋にした後の `return` と、渡し場への `move` は受領判断なしで確定した。解除の後の `move` は拒否された。                                                                                                      |
| 指示                     | 当時あった `companion-order` で「森の入口で、薬草の生えている場所を探しておいてほしい」と伝えた。指示は渡し守の自己照会に載ったが、渡し守は次の手番で公開行動を取らずに手番を終えた。森には薬草の記録がなく、その場で確かめられる指示ではなかった。この結果と手番の条件から、指示の操作を外した。 |

GMの同行判断は3回で計0.0118米ドルだった。
