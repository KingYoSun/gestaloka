# ADR-047: 応答の復元とシーン内参照の出力契約

状態: 採用。必須CIの通過後に本番へ反映する。2026年11月17日のユーザー判断に基づく。

## 原因

#206の復元器は、入れ子のanyOfを探索せず、任意の定数項目をAPI用の包みから外す前に比較していた。復元例外を握り潰すため、指定スキーマに適合する応答もresponse付きのまま後段へ渡り、型判別エラーで修復を繰り返した。

保存255応答で両方の不備を再現した。修正後の生成比較では復元の誤棄却はなくなり費用は減ったが、到達参照や空context等の別の失敗で上位呼出しが増えた。ユーザーはそれらを対象に追加し、引き継ぎ数と総費用をともに減らす条件を維持すると判断した。追加の有料比較には総額1 USDの上限を置く。

本番由来の保存応答は公開対象から削除し、当時の確認結果は集計資料に残す。継続する回帰試験には、本番をコピーせずに作成した架空のプロトコル入力を使う。

追加比較の温室は旧新とも背景生成のpauseで停止した。ユーザーは、温室の完走をPR作成の必須条件にせず、現状の証拠と未確認範囲を示してPR作成へ進むよう指示した。温室の停止原因の改修は今回へ追加せず、有料比較を終了する。

## 決定

復元では入れ子の選択肢を展開し、任意項目の未指定・指定値・明示nullを保って定数を比較する。失敗箇所をパス付きで記録する。原応答と使用量を精算・保存し、復元エラーを既存の形式修復へ渡す。古い修復要求がある場合は、その保存済み要求を再利用し、同じ呼出しIDを新しい修復文へ置き換えない。

シーンの出力スキーマは、既存の実行側検査に合わせて参照先を提示する。行動主体は形成済み意図の主体とし、受容者は入力・取得結果で提示済みの存在を使う。既存発生への受容は、提示済みのシーン履歴のイベントIDと、操作主体以外の受容者へ限定する。未知の参照先が必要なら、既存の追加照会または局所状況の具体化を行い、照会後の新しい要求で候補を更新する。未取得を不存在とは扱わない。

退出入力がない応答では退出欄を出力スキーマから省き、実行側の既存の空配列既定値を使う。退出入力がある場合は、その主体を指定できる。空のcontextを生成せず、性質・解釈・存在・参加の少なくとも一つを含める。形式修復でも履歴・配送本文の照会を可能にし、終了判断は保つ。OpenRouterのスキーマでは、実行側が既に要求する非空文字列の条件も送信する。

同一の保存文脈に対する読み取り照会は、引数が完全に等しいものだけをまとめる。原応答を維持し、異なる照会は打ち切らない。

人物の特定行動や返答、世界の現象を列挙した許可メニューは作らない。モデル割当・推論量・最大出力・再試行回数・保存済み履歴は変えず、内容の検品専用のLLM呼出しも追加しない。実行側の検査は、保存済み応答とスキーマに従わない応答のために維持する。

## 完了判定

1. 保存255応答を、文字列・値・未指定と明示値を変えずに復元し、既存の応答パーサーを通す。復元エラーの記録・精算・修復理由と、保存済み要求の再送防止を試験する。
2. 履歴を取得すると参照候補が増えること、未取得の履歴を照会できること、終了判断を維持すること、空のcontextと不適格な到達・退出指定を出力契約が防ぐことを試験する。
3. 最初の2設定・各2初期状態の旧新8シーンは費用と上位呼出しをすべて保存する。追加比較は、そこで引き継ぎがあった各設定の作業中条件を旧新各1回、計4シーンとする。モデル・人物条件・初期グラフ・最大4入力を固定し、追加照会・修復・世界反映・リザルトを含める。API送信前に全試行の計算済み額と未確定予約を確認し、1 USDを超える送信はしない。
4. 追加比較の全費用と上位呼出しを集計し、完了した記録庫のあらすじ・全応答・リザルトから重要な情報と選択の意味を引用で確認する。保存255応答の値の保持と参照候補の照会による拡張も合わせて判断する。温室の後続提示は未確認と明示し、その完走をPR作成の条件にしない。特定の台詞・行動・結末の一致、指示への正確な追従は採否に使わない。
5. 関連検証と必須CIを通し、マージ後のmainを本番へ反映して実行物とhealthを照合する。
