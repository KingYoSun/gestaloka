# ADR-071: 待受が止まった人物への接触

状態: 採用。#315 の対応方針として、2026年11月21日のユーザー判断を記録する。[ADR-052](ADR-052-player-bot-standby.md)の「期限切れ後は新しい接触の対象から外れる」を置き換える。

## 問題

在席期限（10分）が切れた人物は、接触の対象から外れていた。Museなどの実行環境では、再起動で待受プロセスが止まり、次にViewが起きるまで開き直せない。その間は数十分に及ぶことがあり、所在地が合う相手が訪ねても接触は拒否された。来訪者の側では何も起きず、本人も来訪を知る手段がなかった。

一方、不在の人物の手番はすでに離席として扱える。手番が回る前から不在の人物はスキップし、全員が不在のセッションは保留にする。このため、手番を止めないために在席期限で接触先から外す必要はなかった。

## 決定

- 接触できる相手を、待機を解除しておらず、最終更新から1日以内の人物に広げる。在席期限（10分）は、手番の在席判定と起床の判定に引き続き使う。`disconnect`した人物と1日を過ぎた人物には、従来どおり接触できない。プレイヤー一覧と、一覧からの事前の検索も同じ条件にそろえる。
- 不在の相手への接触でも、相手のセッションを用意して接触した側を合流させる。新しく開いたセッションと保留中のセッションでは、相手の手番は接触の時点で始まるとみなし、相手が不在ならすぐスキップする。接触した側には、相手が離席中であることを応答で伝える。
- 接触した側の発言や行動は、同席者である本人の記録にも残る。本人が待受を開き直すと再開世代が上がり、手番が回った時点で新しい起床キーが出る。接触した側が先に去って本人だけが残ったセッションは保留になり、本人が戻った時点で本人の手番になる。
- 不在の本人の発言・行動・判断を、サーバーが代わりに生成することはしない。待機は実行環境の状態であり、世界内の睡眠などとしては記録しない。

## 受入条件と判定

| 対象                   | 期待結果                                                                                                                           | 判定方法             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| 在席切れの相手への接触 | 待機を解除しておらず1日以内なら合流でき、相手の手番はすぐスキップされて接触した側へ戻る                                            | 時計を進めた結合試験 |
| 復帰後の受け取り       | 待機を再開すると、手番が回った時点で新しい起床キーが出て、不在の間の記録を`status`で読める。接触した側が去った後も同じように読める | 結合試験             |
| 対象外                 | 待機を解除した相手と、1日を過ぎた相手には接触できない                                                                              | 結合試験             |
| 一覧                   | 在席切れから1日以内の人物は一覧に残り、1日を過ぎると外れる                                                                         | 結合試験             |
| 文書                   | スキルと実行環境の手順に、在席切れの間の接触と復帰の扱いを書く                                                                     | 配布文書の照合       |
