# ADR-066 物品の個数と、ダイスの成功による消費

状態: 採用。2026年11月20日のユーザー判断を記録する。

## 背景

物品の消費は、行動する本人が `remove` を申請したときだけ記録されていた。本番のぶー村では、所有・所在がすべて終わった物品は6件で、ほぼ1人のプレイヤーの申請によるものだった。発言（`say`）で使った・食べたと述べても物品は残り、サーバーは行動文から消費を読み取らない。本人の持ち物は別の検索（`belongings`）でしか読めず、サーバー担当のユニークNPCは自分の持ち物を知らないまま行動していた。

物品は個数を持たず、1個が1ノードだった。同じ物を複数持つとノードが個数ぶん増え、「3個のうち1個を使う」は表現できなかった。

物品がプレイに効くのは、GMがダイスを設定するときの材料としてである。GMは申請者の持ち物を読んで成功しやすさを決める。そこで、使った物が減るかどうかも同じ判定で決める。

## 決定

- **本人検索に持ち物を含める。** `search` の `self` は `belongings`（手に持つ物、利用できる保管先とその中身、技能）を返す。検索の種類 `belongings` は廃止する。当面は種類として受け付け、`SEARCH_KIND_MOVED` で本人検索へ誘導する。ユニークNPCに渡すコマンドの形式には含めない。
- **物品は個数を持てる。** 物品のノードに任意の整数 `count` を置く。個数のない物品は、数えないひとまとまりとして扱う。既存の物品はそのまま読める。
- **一部だけを渡す・減らすことができる。** `move`・`transfer`・`remove` に `count` を指定する。省くと全部が対象になる。個数のない物品には指定できない。
  - 一部を渡すと、その個数の物品が渡した先に新しくでき、元の物品は残りの個数になる。
  - 同じ申請で同じ物品に同じ個数を指定した `move` と `transfer` は、同じ取り分に作用する。贈与や売買の一部の受け渡しをこの形で表す。
  - 渡した先に、呼称と所有者が同じ個数つきの物品があれば、新しい物品を作らずその個数に足す。全部を渡した場合は、元の物品の所有・所在を終える。
  - 個数が0になった物品は、所有・所在を終える。
- **個数は `update` で書き換えられる。** 減らすのは本人の範囲でできる。増やす・個数のない物品に新しく付けるときは、新しい物を得る申請として新規作成のダイス（[ADR-059](ADR-059-creation-dice.md)）で判定する。同じ物を得るたびにノードを増やさないためである。
- **ダイスの成功で減る物品は、ダイスの設定と同じGMの呼び出しで決める。** 新規作成のダイスと対抗行動のダイスで、申請者が手に持つ物品を候補（`consumable`）として渡す。GMは成功したら減る物品と個数を `consumes` に返す。死亡判定の `fatal`（[ADR-064](ADR-064-instant-npc-death-and-drops.md)）と同じ構造である。
  - 候補は申請者が直接持つ物品に限る。保管先の中身と、申請自身が操作する物品は候補にしない。
  - サーバーは候補にないIDを捨て、個数を物品の個数までに丸める。`consumes` は呼称とともにダイスの設定へ保存し、応答の `outcome.setting` に含める。
  - 成功したら、申請と同じ確定で減らす。失敗では減らさない。受領を経る申請では、全員の受入で確定したときに減る。
  - 探索（`explore`）のダイスと出現個体の行動では減らさない。GMの呼び出しは増やさない。
- **発言では物品は減らない。** `say` で使った・食べたと述べても持ち物は変わらない。プレイヤーのスキルとhelp、ユニークNPCのシステムプロンプトに明記する。ダイスを通らない消費は、これまでどおり本人が `remove` で申請する。

- **死亡ドロップと検索による出現の物品は、個数つきの1つの物品として残す。** 発生数ぶんの物品を別々に作らず、発生数を個数に持つ物品を1つ作る（[ADR-053](ADR-053-search-appearances.md)と[ADR-064](ADR-064-instant-npc-death-and-drops.md)の変更）。応答の `appearances[].count` に個数が入る。拾うときの `move` に `count` を指定すると一部だけを拾え、残りはその場の発見物として残る。物品以外の出現・ドロップは、これまでどおり発生数ぶんを別々に作る。その場に、呼称が同じ個数つきの発見物が既にあれば、新しい物品を作らずその個数に足す。出現個体の行動などで状態が付いた発見物にも足す。状態が付くたびに別の束ができるのを避けるためで、足した分にも同じ状態が及ぶものとして扱う。該当する発見物が複数あれば、個数の多いものへ足す。応答の `appearances[].id` は足した先の物品のIDになり、`count` は今回現れた数を表す。検索による出現では、その場に落ちている同じ物品（呼称と説明が同じ発見物）の個数と合わせて発生数（`maxCount`、旧形式では `count`）に、検索した人物のセッションに同席するプレイヤーの数（NPCと出現個体は数えず、最低1）を掛けた数を超えないよう、出現数を減らす。上限に達していれば現れず、拾われて減れば再び現れる。出現個体と違い、世界ごとの倍率は掛けない。死亡ドロップには上限を設けない（2026年11月21日のユーザー判断で追加）。

プレイヤーCLIの説明を更新し、0.36.0とする。

本番の既存の物品は、反映時の管理修正で個数を付ける。個数のない物品に個数を付け、同じ保持者のもとで重複している物品は個数つきの1つへ統合する。

## 検証

結合試験で次を確認する。特定の行動や結末は期待値にしない。

- 本人検索が手持ち・保管先の中身・技能を個数つきで返し、`belongings` の検索は誘導のエラーを返して通常枠を使わない。
- 一部を渡すと元の物品の個数が減り、渡した先に同じ呼称の物品があれば個数が足され、なければ新しい物品ができる。同じ個数の `move` と `transfer` は同じ取り分に作用する。
- 個数を指定した `remove` は個数を減らし、0になれば所有・所在を終える。個数のない物品への個数指定は拒否する。
- 個数を増やす `update` はダイスに進み、失敗では個数が変わらない。減らす `update` はダイスを通らない。
- 同じ場所で出現が重なると、その場に残っている同じ物品の個数に足され、物品は増えない。
- 死亡ドロップと検索による出現の物品は発生数を個数に持つ1つの物品として残り、一部を拾うと残りがその場に残る。
- 新規作成と対抗行動のダイスで候補がGMへ渡り、成功すると選ばれた物品が減る。失敗では減らない。候補にないIDは減らない。同じ要求の再送は同じ結果を返す。
