# ADR-082 判定の失敗でファンブルを振り、状態に期限を持たせる

状態: 採用。2026年11月23日のユーザー判断を記録する。[ADR-080](ADR-080-opposition-states-by-gm.md)でGMが返す内容に、失敗時に本人へ残る状態と、状態が続く時間を加える。

## 問題

GMが返すのは成功率と、成功したときに起きる変化だけである。失敗は一律に「何も確定しない」になる。申請の進め方や人物の性格は成功率を変えるが、失敗した後に残るものは変えない。失敗しても通常枠を1回使うだけで、次の手番に同じ状況からやり直せる。

このため、危ない作業を慎重に進めるか雑に進めるかを選ぶ意味が小さい。負傷のような一時的な不利も残らず、その後の場面に影響が続かない。この構造は、行動の種類や世界の設定によらず成り立つ。

状態には付与した時点があるが、終わる時点を先に決める手段が無い。負傷を記録しても、本人が終了を申請するまで続く。

## 決定

- **GMは、ダイス設定にファンブルを加えてよい。** 形は `fumble:{through,text,minutes}` とする。`through` は成功の上限と同じ範囲（1以上、面の数未満）で決める。`text` は、ファンブルしたときに申請者本人へ残る状態である。残る変化がなければ省く。
- **ファンブルの基準は、世界ごとの文で設定する。** 成功の基準（[ADR-059](ADR-059-creation-dice.md)）と同じく、管理者が `creationPolicy.put` の `fumbleCriteria` で設定し、`creationPolicy.read` で確認する。空欄の世界には既定の基準を使い、省略した設定は現在の基準を保つ。`shown` を選んだ世界では、プレイヤーの `status` の `fumbleCriteria` に出る。本文の形式、死亡を含めないこと、期限の付け方は基準で変えられない。
- **ファンブルは、成功のダイスが失敗したときだけ振る。** 同じ面の数でもう一度振り、出目が `through` 以下ならファンブルとする。ファンブルしたら、`text` を本人の状態として、失敗した行動の記録と同じ確定で残す。成功した判定では振らない。
- **対象は作成の判定と対抗の判定とする。** 複数の案や技能ごとの判定では、判定ごとに扱う。新しい場所の `explore`、隠密の判定、乗り物の操縦権の判定には加えない。死亡（`fatal`）は成功時の判定のままで、ファンブルでは起こさない。
- **状態が残る本人は、プレイヤーとユニークNPCに限る。** 出現個体の行動には加えない。
- **出し直しでは振り直さない。** 同じ手番の出し直しで前回の結果を返すとき（`outcome.repeated`）は、ファンブルを振らず、状態も重ねない。同じ要求IDの再送は、保存した出目と結果を返す。
- **状態の期限は、関係の終了時点で表す。** GMは、ファンブルの状態と、対抗行動の成功で相手に残る状態（`states`）に、続く時間 `minutes`（分）を付けてよい。サーバーは、確定の時点に `minutes` を足した時刻を、状態の関係の `period.until` に入れる。新しい項目は足さない。省いた状態は、終了を申請するまで続く。
- **期限の前だけ、現在の状態として読む。** 人物の状態は、読み取りの時刻より後に終わる関係までを現在の状態とする。期限を過ぎた状態は、定期処理なしで現在の状態から外れ、手動で終えた状態と同じ形で履歴に残る。
- **期限の前に、本人が終了を申請できる。** 審査は本人の状態変更と同じで、確定すると関係はその時点で終わる。
- 発言・移動・受け渡しなど、ダイスを振らない行動には事故や負傷を持ち込まない。プレイヤーが自分で申請する状態に期限を付ける形式も加えない。

応答では、`outcome.setting.fumble` でGMの設定を、`outcome.fumble`（`roll`・`success`）で2回目の出目と成否を読める。どちらも、ファンブルを振った判定にだけ載せる。成功した判定や出し直しの結果にGMの設定が載っていると、起きなかった状態を起きたものと読み違えるため、振らなかった判定の結果からは設定を外す（2026年11月23日のユーザー判断）。期限は、本人検索の状態の `relation.period.until` で読める。

## 受入条件と判定

特定の行動や結末、ファンブルの発生率は期待値にしない。

| 対象             | 期待結果                                                                                                                                                       | 判定方法       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| GMへの指示       | 作成の判定と、人物が行う対抗の判定の指示にファンブルが含まれる                                                                                                 | 結合試験       |
| 基準の設定       | 設定したファンブルの基準がGMへの指示に入り、空欄では既定の基準が入る。省略した設定は基準を保つ。表示を選んだ世界では `status` に出る                           | 結合試験       |
| 2回目のダイス    | 成功のダイスが失敗し、ファンブルの設定があるときだけ振る。出目と成否が `outcome.fumble` に入る。振らなかった判定の結果には `outcome.setting.fumble` も入らない | 結合試験       |
| ファンブルの確定 | 出目が範囲内なら本人の状態が残る。範囲外や成功した判定では残らない。相手には残らない                                                                           | 結合試験       |
| 出現個体への作用 | 人物が出現個体へ作用して失敗したときも、本人に状態が残る                                                                                                       | 結合試験       |
| 再送             | 同じ要求IDの再送は同じ応答を返し、状態を重ねない                                                                                                               | 結合試験       |
| 期限             | `minutes` 付きの状態は、確定の時点から `minutes` 分後に終わる関係として残る。対抗行動の成功時の状態も同じ                                                      | 結合試験       |
| 期限の前後       | 期限の前は本人検索に出る。期限を過ぎると出ない                                                                                                                 | 結合試験       |
| 早めの終了       | 期限の前に本人が終了を申請でき、確定すると現在の状態から外れる                                                                                                 | 結合試験       |
| 文書             | ダイスの解説に、ファンブルと状態の期限を書く                                                                                                                   | 配布文書の照合 |

## 影響

- 判定の失敗が「何も確定しない」とは限らなくなる。ファンブルすると、申請していない状態が本人に残る。
- 応答の `outcome` に `fumble` と `setting.fumble` が増える。`setting.states` の各要素に `minutes` が付くことがある。既存の項目は変わらない。
- `creationPolicy.read` の応答に `fumbleCriteria` と `defaultFumbleCriteria` が増える。`creationPolicy.put` は `fumbleCriteria` を任意で受け取る。表示を選んだ世界の `status` に `fumbleCriteria` が増える。
- 関係の保存データの形は変わらない。終了時点が未来の関係が新しく現れる。これまでの関係は、終了時点が確定の時点以前なので、読み方は変わらない。
- 過去の判定の結果は変えない。
- プレイヤーCLIの解説が変わるため、CLIの版を上げる。
