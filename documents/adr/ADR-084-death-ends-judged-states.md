# ADR-084 死亡を復帰として扱い、判定と死亡で付いた状態を現在の状態に残さない

状態: 採用。2026年11月24日のユーザー判断を記録する。[ADR-065](ADR-065-person-death-penalty.md)の死亡の扱いに、終える状態を加える。

## 問題

ADR-065では、死亡した人物は最初の所在地などへ移ってプレイを続ける。しかし、それまでに付いた状態は終わらず、死亡の確定で付いた状態も現在の状態として残る。

例えば、相手の咆哮で耳を傷めた直後に噛みつかれて死亡した人物は、移った先でも耳の負傷を抱えたままになる。さらに「頭部が砕けている」「死亡している」といった状態も残るので、死んだ体のまま行動を続けることになる。死亡の後に続けられる仕組みと、死亡を表す状態が残る仕組みが食い違っている。この構造は、行動の種類や世界の設定によらず成り立つ。

判定で付いた状態とほかの状態は、関係の形が同じなので区別できない。期限は、GMが続く時間を付けた状態にしか無い。

## 決定

- **死亡は復帰として扱う。** 死亡した人物は、ADR-065のとおり移った先で続ける。死亡の前に判定で負った状態も、死亡そのものを表す状態も、復帰後の現在の状態には残さない。死亡の経緯は、出来事の記録と目撃に残る。
- **判定で付いた状態の関係に、印を付ける。** 対抗行動の成功で相手に残る状態（`states`）、ファンブルで本人に残る状態、出現個体の作用で人物に残る状態は、status/content の関係の `text` を `judged` にする。所在の `location` や行き来の `route` と同じく、関係の内容で役割を表す。新しい項目は足さない。
- **死亡を確定するとき、本人の現在の状態のうち、印のあるものと期限のあるものを終える。** 死亡による移動と同じ確定に、関係の終了を加える。期限のある状態は、印を付ける前に作られた判定の状態も含めるために対象にする。
- **死亡を確定した差分で本人に付く状態は、終わった関係として記録する。** GMが返す状態も、申請の変更に含まれる状態も対象にする。関係の終了時点を付与の時点と同じにし、履歴には残すが現在の状態には出さない。
- **終えないもの**: 本人が申請して記録した状態、所在などの印の違う関係。印を付ける前に作られた、期限のない判定の状態も終えない。過去の記録は改めない。

## 受入条件と判定

特定の行動や結末は期待値にしない。

| 対象             | 期待結果                                                             | 判定方法       |
| ---------------- | -------------------------------------------------------------------- | -------------- |
| 判定で付いた状態 | 死亡の前に判定で付いた状態は、死亡の確定で現在の状態から外れる       | 結合試験       |
| 期限のある状態   | 印のない期限つきの状態も、死亡の確定で現在の状態から外れる           | 結合試験       |
| 死亡で付いた状態 | 死亡を確定した判定で付いた状態は、記録に残るが、現在の状態には出ない | 結合試験       |
| ほかの状態       | 判定によらない期限のない状態は、死亡の後も残る                       | 結合試験       |
| 文書             | 死亡で終わる状態と残る状態を、プレイヤー向けの解説と変更履歴に書く   | 配布文書の照合 |

## 影響

- 状態の関係に `text: "judged"` が付くことがある。保存データの形は変わらない。
- 死亡の確定で、本人の状態の関係が終わる。終わった状態は、手動で終えた状態と同じ形で履歴に残る。付与と同時に終わる関係が新しく現れる。
- 印を付ける前に死亡した人物に残っている状態は、この変更では終わらない。必要なら管理修正で終える。
- プレイヤーCLIの解説が変わるため、CLIの版を 1.21.3 に上げる。
