# ADR-079 外部botが担当するNPCの同行は本人が決める

状態: 採用。2026年11月23日のユーザー判断を記録する。[ADR-076](ADR-076-npc-companions.md)の成立と解除を、外部botが担当するNPCについて改める。

## 問題

ADR-076は「NPCには自分で承諾する主体がない」ことを前提に、同行の可否をGMが判断し、解除をプレイヤーだけの操作にした。この前提は、サーバーが担当するNPCには当てはまる。外部botが担当するNPC（`bot_npc.controller='bot'`）は、プレイヤーと同じCLIで自分の手番を取り、受領も自分で判断している。

ぶー村の記録（2026年11月23日）では、外部botが担当するNPCがプレイヤーのcompanionになっていた。別の会話でこのNPCに説明を求める声が上がったとき、NPCは自分の判断でその場へ向かえなかった。待機中の出発はサーバーが断り、NPCの側には同行を断る手段も終える手段もなかった。

## 決定

- **申請は本人の受領で決める。** 外部botが担当するNPCへの `companion-request` は、GMの判断を経ずに、同じセッションでの本人の受領へ回す。承認されると、同行の関係の記録と索引への登録を同じ確定で行う。却下か受領期限切れなら成立しない。GMを呼ばないので、SPは使わない。申請は通常の受領と同じく、通常枠を1回使う。
- **成立後は本人から終えられる。** companionになっているNPC本人は、自分のIDを指定した `companion-dismiss` で関係を終えられる。手番は要らない。終えた後は、待機中の出発の制限も掛からない。
- **サーバーが担当するNPCと担当者のいないNPCは変えない。** これまでどおりGMが判断し、解除はプレイヤーが行う。
- 対象の制限（同じセッションにいること、他人のcompanionでないこと、3体まで）は、どちらの経路でも申請の時点で確かめる。

## 受入条件と判定

| 対象            | 期待結果                                                                                   | 判定方法       |
| --------------- | ------------------------------------------------------------------------------------------ | -------------- |
| 本人の却下      | 関係はできず、一覧にも出ない。GMは呼ばれず、SPは減らない                                   | 結合試験       |
| 本人の承認      | `status` の関係がグラフに残り、追従で一覧に出る                                            | 結合試験       |
| 本人からの解除  | NPC本人の `companion-dismiss` で、一覧とグラフの関係が終わる。同行していなければ拒否される | 結合試験       |
| サーバー担当NPC | GMの判断で成立し、SPを使う（ADR-076の受入条件のまま）                                      | 結合試験       |
| スキルの解説    | 外部botが担当するNPCへの申請が受領に回ることと、NPC本人が関係を終える操作を書く            | 配布文書の照合 |

## 影響

- プレイヤーから見ると、外部botが担当するNPCへの同行申請は、すぐには結果が出ず、相手の回答を待つ形になる。応答は `state: "receiving"` で、結果は受領の通知で読む。
- 成立済みの同行は変わらない。NPC本人が終えるまで続く。
- プレイヤーCLIの解説が変わるため、CLIの版を上げる。
