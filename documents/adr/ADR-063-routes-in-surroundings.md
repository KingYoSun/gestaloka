# ADR-063 行き来の記述に印を付け、周囲の検索で繋がっている場所を返す

状態: 採用。2026年11月20日のユーザー判断を記録する。

## 背景

探索しているプレイヤーが、いまいる場所からどこへ行けるかを知る手段がなかった。`explore` は接続元と新しい場所に同じ記述を付けるが（[ADR-060](ADR-060-explore-places.md)）、この記述は普通の状態の記述と同じ形をしている。場所を表すノードの種別もない。周囲の検索は、どの記述が行き来を表すかを判定できなかった。

## 決定

- **行き来の記述に印を付ける。** 場所から行き来の記述への `status/content` の `text` を `route` とする。地面に残った物（`ground`）や所在（`location`）と同じ方式である。`explore` は、接続元と新しい場所の両方にこの印を付ける。
- **周囲の検索は、繋がっている場所の名前とIDを返す。** `search` の `surroundings` に `routes`（`id` と `label`）を加える。本人が直接滞在している場所から、印の付いた記述がほかに参照している対象を返す。所在の記録が参照しているだけの場所（村全体など）からは集めない。印のない記述は読まない。詳しい内容は、返ったIDを対象にした検索で調べる。
- **移動は制限しない。** `routes` は手がかりで、`locate` の行き先はこれまでどおり検索結果で受け取ったIDなら指定できる。
- **印のない既存の記述は、管理修正で付け直す。** 以前の `explore` が作った記述と、初期の場所どうしの行き来は、管理者が `worlds.edit` で印の付いた関係にする。初期世界の生成で行き来を作ることは、この決定に含めない。

- **同じ呼び名の場所は `explore` で増やさない。** 行き来の記述で結ばれた場所に同じ呼び名があれば、GMを呼ばずに `EXPLORE_NAME_TAKEN` で拒否し、先にある場所のIDをメッセージで返す。通常枠は使わない。物や人物の呼び名とは比べない。
- **新しい参加者の住まいは、参加の確定で行き来を結ぶ。** 参加の指示文に印の付け方を加える。住まいと既存の場所との行き来が、参加者の基本設定や世界の記録から定まる場合に、参加の提案が行き来の記述を作る。どの場所と結ぶかは世界ごとの基本設定で決まり、コードには持たない。

プレイヤーCLIの説明を更新し、0.32.0とする（`routes` の追加は0.31.0）。2026年11月20日の試遊で、所在の記録が参照する場所すべてから集めると隣り合わない場所まで並ぶこと、同じ呼び名の場所が複数できていたことが分かり、同日のユーザー判断で上の2点と直接の滞在先への限定を加えた。

## 検証

結合試験で、`explore` が成功した後、接続元にいる人物の周囲の検索が新しい場所だけを `routes` に返すこと、新しい場所へ移った後は接続元を返すこと、印のない状態の記述が参照する対象を返さないことを確認する。同じ呼び名での申請がGMを呼ばずに拒否されて先にある場所のIDが返ること、直接の滞在先でない場所の行き来が返らないことも確認する。参加の提案が行き来の記述を作ることは、モデルの出力に依存するため結合試験では固定しない。
