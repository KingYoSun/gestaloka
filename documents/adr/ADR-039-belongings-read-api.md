# ADR-039: 持ち物・保管先・技能の本人向け取得

状態: 採用。2026年11月15日。

## 対象

[#172](https://github.com/KingYoSun/gestaloka/issues/172)を扱う。[ADR-037](ADR-037-belongings-and-skills.md)の関係を、本人がWebとプレイヤーCLIから読めるようにする。書き込み用の内部関数は公開しない。

## 決定

`GET /api/worlds/{id}/belongings` を追加する。応答は、携行している物品、利用できる保管先とその在庫、技能の三つを持つ。WebとCLIは同じAPIを使う。

- 認可は本人の知識の取得と同じ規則を使う。Webは選択した人物との対応を確認し、CLIは許可された人物だけを読める。許可を解除した後のCLIは拒否する。
- 保管先は、本人に `use` の関係があるものだけを返す。別の人物の携行品・技能は返さない。
- 在庫は照会時点の最新の確定状態を返す。保管先から離れていても、初めて読む場合でも、同じ在庫を返す。閲覧者ごとの版や閲覧時刻は持たない。
- 取得は関係を読むだけとする。観測・出来事・世界内の時点を変えず、モデルも呼ばない。

同じ呼称の物品は一行にまとめ、個数を `quantity` として返す。所有については、本人の所有かどうかを `mine` で返す。所有者の名前は返さない。所有者が誰かは世界の事実であり、本人が知っているとは限らないためである。

Webはシーン画面に「持ち物と技能を見る」を置く。シーン画面はシーンの外でも表示するため、シーンの内外から開ける。開くたびに読み直す。CLIには `inventory`・`storage`・`skills` を追加し、それぞれ応答の該当部分をJSONで出力する。

## 検証

- 結合テストで、同じ人物についてCLIの三つのコマンドとWebが使うAPIの応答が一致することを確認した。取得の前後でシーンの状態・世界内の時点・本人の観測の件数が変わらず、モデル呼び出しが0回であることも確認した。
- 共同倉庫の最後の一品を別の利用者が持ち出した直後に、閲覧済みの人物、初めて読む人物、持ち出した本人が同じ空の在庫を読むことを確認した。
- 利用権のない保管先と他人の持ち物が応答に含まれないこと、他人の人物を指定した照会と許可解除後のCLIが拒否されることを確認した。
- Webの単体テストで、シーンの外と中の両方から開けること、開くたびに読み直すことを確認した。
