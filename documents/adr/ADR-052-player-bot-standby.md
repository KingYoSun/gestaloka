# ADR-052: 待機中のbotへの接触と起床

状態: 実装・検証中。2026年11月18日のユーザー判断を記録する。Museプレイヤーはプレイ中以外、待機を基本とする。

## 問題

旧招待・反応・投票APIを廃止した際、CLIの待機・通知の導線も削除した。新しい手番APIでは、相手がシーンを開いていなければ接触できず、常時起動していない本人のbotへ判断を戻す導線も不足していた。一般参加botのNPC代演を廃止する以上、本人を軽量に待機させ、必要なときに起こす仕組みが要る。

## 決定

待機は人物・接続ごとの実行環境の状態とし、世界内の睡眠などを自動で記録しない。認証済みの待機登録・更新・解除を専用APIで扱う。通常の操作は接続を有効にし、状態照会はその接続の既存の待機だけを更新する。一般の参加botの切断をサーバーNPCへの切替理由にしない。

在席期限は従来どおり10分。Museの軽量フックは60秒間隔、バックグラウンドCLIは30秒間隔で更新する。これらの処理で生成LLMを起動せず、通常APIコール枠と報告枠も消費しない。期限切れや解除後は、新しい接触の対象から外れる。

確定した所在地が合い、在席する操作担当を確認できた相手には、シーン外の待機中でも接触できる。その場合は本人のセッションと一続きのシーンを用意し、接触した側を合流させ、本人へ手番を渡す。用意するのは進行のメタデータで、本人の発言・行動・協力は生成しない。明示指定されたサーバーNPCは既存の担当処理を使う。

本人が実行できる通常手番または受領判断があるとき、待機APIは`actionable`と`wakeKey`を返す。キーにはセッション・手番・判断段階・公開された記録の版・参加人数・接続の再開世代を反映する。受領後に同じ元手番へ戻るときも改めて起こせるよう、手番番号だけで通知を抑えない。自分の手番の途中の検索・発言では、起床キーを増やさない。

CLIの`standby`は一度だけ更新して状態を返す。`listen`はバックグラウンドで維持し、状態変化をJSON Linesで返す。`disconnect`はインスタンスごとの待機を明示的に終え、フックの次回実行が勝手に再開しないよう有効状態を要求履歴と別に保存する。再開は`standby --resume`で行う。待機更新は最後の要求IDを書き換えない。

Museでは参加準備が完了したらゲーム用フックと待機を設定し、プレイ終了後や他者の判断待ちにも維持する。同じVMを使うGrok Botでは、実行・起床先・通知済みキーをViewごとに分ける。ランタイムは本人のViewが待機中で、未通知の作業があるときだけ起こす。通知の受付に成功したキーだけを保存し、起きた本人は`status`から現状を読み直す。

## 受入条件と判定

| 対象             | 期待結果                                                     | 判定方法                                           |
| ---------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| シーン外の待機   | 待機を保ったままシーンを閉じ、後からの接触で本人へ手番が届く | API・CLIで接触前後のメタデータと起床キーを照合     |
| 在席と再開       | 更新が途絶えると接触できず、明示的な解除と再開を区別する     | 時計を進めた結合試験で確認                         |
| 受領からの復帰   | 元の同じ通常手番にも新しい起床が届く                         | 受領前・判断中・判断後のキーを比較                 |
| 通知の重複       | 同じ作業や手番途中の検索だけでは追加起動を要求しない         | 複数回の照会と検索でキーの安定を確認               |
| View別の待機     | 一方の解除が他方へ影響せず、復旧用の要求記録を保持する       | 同じVMの2インスタンスで確認                        |
| バックグラウンド | LLMが動いていない間も待機を維持し、後からの接触を出力する    | 待受プロセスを起動し、別の実行から接触する結合試験 |
| スキル           | Museの基本待機、View別通知、再開・解除まで説明する           | CLIの出力と配布文書を照合し、スキルと参照先を検証  |

現在のムジーナへの依頼はユーザー指定によりログ評価に限り、実機の待機再登録や本番への接続はこの検証では行わない。
