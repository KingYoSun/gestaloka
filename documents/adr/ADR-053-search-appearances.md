# ADR-053: 検索で発生する存在と物品

インスタントNPCの同席・手番、発生数の範囲、同席中の昇格後の動作は[ADR-056](ADR-056-instant-npc-turns.md)に従う。

発生用ノードは `script` とし、世界生成時にも生成後にも同じグラフ差分で追加できる。`spawn` は出現対象の `kind`（instant-npc、existence、script、event）、呼称 `species`、説明 `description`、0〜1の `probability`、1回の当たりで発生する正の整数 `count` を持つ。

発生用scriptは主体からstatus/contentで関連付ける。scriptから検索対象へのstatus/aboutのtextを `spawn-hit`、必要な現在地へのstatus/aboutのtextを `spawn-at`、必要な保持物へのstatus/aboutのtextを `spawn-hold` とする。本人が受け取る検索結果に依存先が含まれ、本人のhas/holdが全条件を満たしたとき、発生用ノードごとに1回だけ抽選する。新しい検索では再抽選する。同じ要求の再送は外れを含めて確定済みの結果を返す。

当たりならcount個を別々のIDで記録する。その時点の同席者が出現を共有する。検索素材は本人にだけ返す。物品はその場に保持者なしで残る。後から来た人物も周囲を検索し、moveで同じ物品を拾える。インスタントNPCは出現の記録だけが残り、管理者の昇格許可を経てユニークNPCになる。手動の登場申請は新規作成の判定を通す。

出現時に観測できる描写は、発生用scriptから候補のscriptへ `status/about` の `text` を `spawn-description` として結ぶ。候補には、その発生条件が成立した場面で観測できる内容を書く。同じ候補を複数の発生用ノードで共有できる。一度に何体出ても、発生用ノードごとに、公開できる空でない候補から一つを等確率で選ぶ。

選んだ描写を出現イベントの本文に加え、その本文を検索結果の `appearanceText` と同席者の公開ログで共有する。再送では確定済みの本文を使う。候補がない場合は従来の出現通知を使う。

本人の解釈や本人が保持する物の破棄は通常更新で扱う。対抗行動では対象や関係を構築できなければ失敗し、外界に作用する関係が成立すればGMが設定したダイスで成否を決める。

体験の調査には参加者の報告と管理者のMCPを使う。独自の観客機能は設けない。
