# ADR-006: 世界構築と村民の画面

状態: 画面実装と自動検証を完了。実モデルの通常行動の品質は継続検証。2026-10-19。

## 完了範囲

Issue #32・#34の最初の村を、同じSPAの管理画面と村民の画面から操作する。初期入力、進行期間、区切りの報告、追加進行、明示完了、別村民への参加、自由記述行動、再読込後の復帰を確認する。モデルの内部文脈やグラフ編集は画面へ出さない。

管理者の期間指定は最小1日・1日単位とする。日数を初期値1の整数入力で受け付け、APIと構築処理でも端数や1日未満を拒否する。内部時刻や相互作用の刻みを1日へ丸めない。

公開契約の静的型を生成HTTPクライアントへ接続し、SSEは公開Zodスキーマでも検証する。サーバー取得はTanStack Query、URLはTanStack Router、入力はReact Hook FormとReactの状態で管理する。APIへのBFFは追加しない。

## 閲覧と操作の境界

管理画面は管理者向けの報告を、村民画面は本人の観測・解釈と自身の入力を表示する。受付・進行・保留・次の入力待ちを区別し、受付や操作返却を世界内の成功として描写しない。入力の受け付け後は、ブラウザーを閉じてもサーバーの処理を止めない。

人間の行動文はそのまま送信し、操作対象や行動種別をクライアントの隠し項目で決めない。未確認の送信は要求IDと本文を保持し、再送を別の行動にしない。IME変換中や変換確定のEnterで送信しない。

## 取得・再接続・キャッシュ

認可された配信位置を先に取得し、その位置からの通知と新しいスナップショットを組み合わせる。切断時も同じ手順で再取得し、標準EventSourceの再接続だけに依存しない。配信位置と世界内の時点を混同しない。

主体・認可の世代ごとにQueryClientを分け、世界・ロール・観測主体に応じて取得を分離する。認可コンテキストの変更では購読・リクエスト・キャッシュを整理する。HTTP応答の主体と、村民のviewerIdも確認し、遅れて届いた旧文脈の応答を別主体へ反映しない。

## ログと表示

履歴は前後のcursorで取得し、TanStack Queryの保持は4ページ、表示はTanStack Virtualで必要な範囲だけにする。1ページ50件の総履歴上限にはしない。前後の追加取得とページ破棄では、表示中の記録のキーと行内の位置を基準にスクロールを保つ。過去を読んでいる間の更新は知らせ、最新への移動は利用者が行う。

Markdownはreact-markdownとremark-gfmで描画し、生HTMLは解釈しない。本文はDESIGN.mdの読み幅・文字サイズ・行間を使う。ライト・ダークと狭い画面を確認し、装飾で本文の階層を増やさない。

## 判定方法

Vitest・React Testing Library・MSWで、入力と状態、IME、主体変更、SSE重複と再取得を確認した。Playwrightは実API・独立ワーカー・DBを使い、構築から行動・再読込、狭い画面、長い履歴の保持量とスクロールを確認した。テスト用プロバイダーはtests配下だけに置き、本番の世界更新へ固定の展開を持ち込まない。

実モデルでも同じ画面から実行した。[画面と推論量の評価](../evaluations/gameplay-ui-2026-10-19.md)に、成立した範囲とnoneの問題を記録する。画面操作が完走したことを、世界更新の意味的な品質の合格とはしない。
