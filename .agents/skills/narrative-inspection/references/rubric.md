# meaning-v6

入力ごとの新情報量は`inputs.units`、あらすじとリザルトの新情報量は`otherPresentations.units`に記録した意味単位のうち、`duplicate`を除く数として報告する。全体はその合計。対応資料が不十分なら全体の数はnullにし、確認できる単位と不足を残す。復唱を別の言葉にしただけなら重複。同じ対象への新しい理解は再解釈として扱える。これはグラフ要素数と一致する必要はない。

新しい意味単位は、以前の命題と今回の命題の差で判定する。「整理された」「明確になった」「確定範囲を説明した」という説明だけでは、更新・再解釈・確度変化へ数えない。以前の理解を変える観測・証言・根拠・状態変化が今回の提示にあるかを確かめる。

| 比較元と今回の提示                                                                                         | 判定の基準                                                               |
| ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 既に「まだ合意していない」「作業は未着手」「理由は不明」と提示され、リザルトでも同じ未解決事項を説明する   | 重複。未解決であることの再掲は確度変化ではない                           |
| 本人の設定や準備目的を、あらすじが役割の再掲と意図の言い換えで述べる                                       | 重複。意図の言い換えを行動の進捗へ変換しない                             |
| 以前の提示が「忙しそうに見える。細かい事情は断定していない」、リザルトが「印象にすぎず理由は不明」と述べる | 重複。新しい裏付けも信頼度の変更もない                                   |
| 作業を申し出た後、実行とその成果が観測として提示される                                                     | 予想どおりでも実行結果は新情報になり得る。入力の復唱と成果の提示を分ける |
| 新しい観測・検証・出典によって、既知の証言の信頼性や範囲が変わる                                           | 確度変化の候補。以前と今回の根拠、変わった信頼性や範囲を示す             |

更新・再解釈・確度変化には、比較元の引用と今回の引用を選ぶ。設定や入力済みの意図が比較元なら、その出典を説明で特定する。新しい根拠や理解の変化を特定できない単位はduplicateにする。語尾、要約の形式、管理上の記録の言い直しだけでは加点しない。

あらすじ・リザルトは新規性とは別に、提示済みの状態と知識の確かさの継続を全引用について照合する。既知の状態を根拠なく未確定へ弱める文を、重複や妥当な確度変化として処理しない。以前から未解決だった問いの再掲と、既知の事実を不明にする変更を分ける。変化の根拠があればその出来事・観測を、なければ比較元と問題の文を選んで不一致へ記録する。新たな提示がないだけで未知や否定を補わない。

`missing`には、意味評価に必要な提示本文・入力・既知の履歴が取得できない場合だけを記録する。物語内で原因や将来が未解決であること、満足度を実測していないことは資料の欠測ではない。これらの限界は説明に残す。`information`がnullでも本文が保存されていれば、本文の意味単位と引用は評価できる。グラフとの構造対応の欠測は決定論的測定と不一致の説明に残し、意味評価の欠測へ置き換えない。

重要度は「この情報を取り除くと、状況理解、人物・関係の解釈、今後の予想、選択の判断がどれだけ変わるか」で判定する。

| 段階 | 判定                                         | 適用例                                   |
| ---- | -------------------------------------------- | ---------------------------------------- |
| 0    | 取り除いても理解・予想・判断が変わらない     | 入力を言い換えただけの復唱               |
| 1    | 局所的な理解が少し変わる                     | 予想どおりに扉が開いたという結果         |
| 2    | 人物や場面の理解、次の判断材料が変わる       | 拒否の理由、関係の判明、情緒的な理解     |
| 3    | 中心的な理解や予想、選択の前提が大きく変わる | 信頼の意味が変わる開示、重要な証言の確証 |

人物交流や情緒の理解を、攻略に直結しないという理由だけで低く扱わない。全体の重要度は、確認できた新しい意味単位の重要度の平均とし、単位がなければnullにする。情報量と合算した総合点は作らない。

応答性はresponsive（入力の試み・問いへの結果や証拠がある）、partial（一部だけ）、unresponsive（復唱や無関係な進行のみ）、unknown（根拠不足）。成功・驚き・不確実性の減少は必須条件ではない。予想どおりの結果、理由のある拒否、謎の追加、証言から確証への変化も評価する。

複合入力は、頼んだ各部分の結果を確かめる。「観察した」「確かめた」だけでは、何が見えた・聞こえた・変わったかの結果にならない。作業の実行は返ったが、併せて求めた観察内容が返らなければpartialとする。見えなかった場合も、実際の遮蔽や知覚範囲などの根拠が返れば結果である。単なる記録不足から「何もない」と推定しない。本文が実際に保存されているこの問題を、資料の欠測やunknownへ置き換えない。

原則適合はconsistent、violation、unknownを別項目にする。入力にない同意や次の選択をプレイヤーが行ったことにする記述は違反の候補であり、因果の根拠と明示入力を照合する。物語が不都合な結果になっただけでは違反としない。

停滞は、意味上の新情報が確認できない入力の連続と、入力の目的・場面の文脈を合わせて説明する。不足を停滞や0点へ置き換えない。決定論的に増えた別IDが同じ意味を繰り返す場合や、同じIDの再解釈に意味の変化がある場合は、不一致の具体例として記録する。固定重みや段階を普遍的に正しい尺度とは扱わない。

応答性は共通の応答判定契約に従う。届いた内容と未完了の部分を明示し、未着手・途中・先送りはincompleteとして未回答に残す。拒否や失敗を認めることと、単なる未実施を完了にすることを混同しない。項目内の部分回答はpartial-contentとして回答済みと未回答の両方へ集計する。全項目が回答または根拠のある終結ならresponsive、一部だけならpartial、全て未回答ならunresponsiveとする。保存済みの応答が不足していることを資料の欠測へ置き換えない。
